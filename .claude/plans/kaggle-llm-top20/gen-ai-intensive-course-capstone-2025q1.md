## Per-winner synthesis

### Top 10 #1: Gemini Customer Support Agent (amelnozieres)
**Source:** notebook returns 403 (no longer public); synthesis from the [Substack blog](https://decryptai.substack.com/p/how-i-built-a-smarter-genai-customer) via WebFetch, so detail is second-hand.

**Problem and user.** A business support team triaging customer emails. The author upgraded an earlier basic auto-responder (whose classifier was TF-IDF + logistic regression) into a Gemini agent that classifies, retrieves, checks live data and evaluates its own replies.

**Pipeline.** One function, `support_agent_pipeline_gemini()`: merge subject + body -> **zero-shot classification** into `refund_request`, `payment_issue`, `order_status`, `general_inquiry` -> **priority detection** combining keyword rules with Gemini tone classification (high/normal/low) -> **RAG**: embed the email with `text-embedding-004`, retrieve the top 3 support articles -> short-term memory of the customer's previous message -> **function calling**: a typed `get_invoice_info` tool over a mock `invoice_db` -> reply generation with few-shot tone control -> **structured JSON output** with metadata and an escalation flag `needs_human_review = true` when unsure -> **Gemini self-evaluation** of the reply -> CSV logging (tone, token usage, category). A retry wrapper handles rate limits; persistent failure sends a polite fallback and flags for human review.

**Data.** Support articles as the knowledge base and a mock invoice DB; no dataset size given. **Model:** Gemini (version not stated in the blog). **Frameworks:** none named (no LangChain/LangGraph/vector DB mentioned).

**Evaluation.** LLM-as-judge self-scoring per interaction; no accuracy, latency or satisfaction numbers. **Deployment:** notebook only; backend integration is future work.

### Top 10 #3: GenAI-Powered NECP Analysis & Comparison Engine (kianjn)
[notebook](https://www.kaggle.com/code/kianjn/smart-policy-assistant), about 2,600 words.

**Problem and user.** Researchers, policymakers, NGOs and consultancies comparing EU **National Energy and Climate Plans** (NECPs): hundreds of pages per country, unstructured, inconsistent across countries, partly multilingual. Goal: turn the PDFs into a queryable, comparable database.

**Pipeline (sequential, no agents).** (1) `pdfplumber` PDF-to-text and cleaning; input PDFs from a Kaggle Dataset (number of countries not stated in the notebook text). (2) **LLM structured extraction:** Gemini reads each country's (possibly concatenated, long) text with a role-play prompt and returns **only a predefined complex JSON** of key targets, capacities and policy details, with explicit handling of missing data; `max_output_tokens` set. (3) Pandas aggregation into one CSV "database". (4) **"CSV RAG":** a first LLM call parses the user question into a comma-separated list of valid column names or "NONE" (structured output, `temperature=0.1`), the code retrieves those rows/columns, and a second LLM call synthesises an answer **only from the retrieved facts**.

**Model.** `gemini-1.5-flash-latest` via `google-generativeai` and `langchain-google-genai`. **"MLOps":** retry with exponential backoff on `ResourceExhausted` (429), honouring API-suggested delays.

**Evaluation.** None; the author lists extraction-accuracy validation (GenAI evaluation) as future work, along with agents/function calling for ranking and averaging queries, token-based context management, and a hybrid text RAG with embeddings for qualitative questions.

**Why it stands out.** Rather than chatting over PDFs, it extracts a schema first and answers from structured data, so answers are grounded in a table the user can inspect.

### Top 10 #4: Genne: Gen AI Powered Emission Intelligence System (dnkumars, morpho23, samudralahareesh)
[notebook](https://www.kaggle.com/code/dnkumars/genne), about 3,800 words (heavily styled HTML headers, explanation-per-snippet tables).

**Problem and user.** Emissions data locked in unstructured PDF reports; the demo report covers mainly **Indian cities** (city, year, emissions in MtCO2e, source).

**Pipeline.** (1) LangChain `PyPDFLoader`, line cleaning and regex splitting on numbered entries. (2) **Structured generation with `gemini-2.0-flash`** via the `google.genai` SDK: `temperature=0.1`, `response_mime_type="application/json"` and a `response_schema` (`emission_report`), one call per line, errors logged and skipped -> `emission_reports.csv`. (3) **Embedding-based geocoding:** the GeoNames `cities500` dataset (~185,000 places, CC BY 4.0) embedded with **`all-MiniLM-L6-v2`** (sentence-transformers, not Gemini) into a **FAISS `IndexFlatL2`**; each extracted city name is matched to coordinates by nearest neighbour, which tolerates misspelled or partial names. (4) A **Folium** map with marker clusters, screenshotted headless with Selenium/Chromium. (5) **OpenCLIP ViT-B-32** scores the map image against text descriptions to produce a "map insight" with a confidence. (6) A **LangChain `CONVERSATIONAL_REACT_DESCRIPTION` agent** on Gemini with three tools (`EmissionFactTool`, `CityCoordinateTool`, `MapInsightTool`) and `ConversationBufferMemory`, served in a **Gradio** chat UI with streaming.

**MLOps.** `google.api_core.retry` wrapper on `generate_content` for 429/503.

**Evaluation.** None. **Notable:** the only winner that mixes Gemini with open-source embedding and vision models (MiniLM, CLIP) and pairs vector search with a geographic gazetteer.

### Top 10 #5: Inclusive Classroom Assistant (monahamid90, JunLoh, chonghunyee, Sudharshanm2307)
[notebook](https://www.kaggle.com/code/chonghunyee/capstone-project-inclusive-classroom-assistant), about 2,800 words.

**Problem and user.** **Deaf and hard-of-hearing students** who cannot follow live lectures and depend on note-takers or interpreters. Turn lecture audio into a searchable transcript, grounded Q&A and self-test quizzes.

**Pipeline.** (1) **Audio understanding:** upload lecture audio in Gradio; Gemini transcribes it via the file API with a controlled "plain text, no hallucination" prompt. (2) LangChain `RecursiveCharacterTextSplitter` into overlapping chunks -> Gemini embeddings -> **ChromaDB**. (3) **LangChain RAG chain** with Gemini Flash, few-shot examples to cope with small transcription errors, answers grounded only in the uploaded lecture. (4) **Quiz generation:** few-shot prompt producing **5 multiple-choice questions as JSON** (LangChain `JsonOutputParser`), with scoring, streaks and pass/fail colouring. Global state variables act as session memory (`full_transcript`, `vector_db`, `rag_chain`, `quiz_state`).

**Data.** Own test set of **4 lecture audio files** chosen to stress transcription: short clean, medium with moderate noise, long clean, long with heavy noise. No accuracy figures (no WER) reported.

**Model.** "Gemini Flash / Pro" (exact versions not stated in the notebook text). **UI/deployment:** a retro arcade-themed Gradio Blocks app (Minecraft/pixel fonts, 3 tabs) **deployed to a Hugging Face Space** (`MonaHamid/inclusive-classroom-assistant`); FastAPI installed for possible web-service deployment.

**Evaluation.** Qualitative across the 4 audio conditions; limitations section notes transcription accuracy degrades with audio quality.

### Top 10 #6: RAGLab: an automated evaluation tool for configuring RAG pipelines (waltvenable)
[notebook](https://www.kaggle.com/code/waltvenable/capstone-project-raglab), about 3,200 words. The only winner whose product **is** an evaluation harness.

**Problem and user.** Developers building domain RAG chatbots who must choose among query-rewrite methods, embedding models and generation models by trial and error. RAGLab runs a **grid of pipeline variants** against a question set with gold answers and grades every answer. Demo domain: the author's own **Lewiston-Auburn (Maine) Rotary Club** chatbot, knowledge base in ChromaDB.

**Design.** Test definition = questions + gold answers + **per-question judging instructions** ("must contain all elements of the sample answer" vs "need only be similar"). Modular stages, each with swappable functions and models: **pre-retrieval** (`query_rewrite_1` verbose, `query_rewrite_2` concise, `HyDE_1` hypothetical document), **retrieval** (`getknowledge` from ChromaDB, default embeddings, top 5), **generation** (`query_llm`), **judging** (`judge_answer` LLM judge, or `human_judgment_flow`). The judge returns JSON with **Relevance, Faithfulness, Completeness on 1 to 5 plus a 0 to 1 confidence**; composite = 0.4R + 0.4F + 0.2C. **Human-in-the-loop fallback:** if confidence < 0.20 or no gold answer exists, RAGLab pauses and shows a human the question, answer, gold answer and rubric. Every run logs a tab-delimited row (run ID, every stage's function and model, prompts, retrieved knowledge, answer, scores); token, latency and "quality per dollar" columns are planned.

**Models.** Pre-retrieval and judge `gemini-2.0-flash`; generation `gemini-2.0-flash` vs `gemini-2.0-flash-lite` (`gemini-1.5-flash-8b` commented out).

**Evaluation scale (from the notebook config).** The shipped demo is small: **2 questions** ("Who is the president?", "When are meetings?") x **6 configurations** (3 pre-retrieval methods x 2 generation models), summarised as a Markdown table; the spec says production use would be 30 to 200 questions. Results are not quoted in the notebook text.

### Top 10 #7: Scribbles: Tone-aware Writing Agent (ttuuii)
[notebook](https://www.kaggle.com/code/ttuuii/scribbles-tone-aware-writing-agent), about 3,000 words.

**Problem and user.** People who feel awkward or "invisible" posting on LinkedIn-style platforms and do not want to sound like a template. Scribbles optimises for **tone fidelity**, not virality: it turns rough ideas into posts in the user's own voice and suggests light "lens-cleaning" improvements rather than rewrites.

**Data.** The user's own writing samples (pasted or uploaded as .txt/.docx/.pdf via PyMuPDF and python-docx).

**Design.** Samples are embedded with **`text-embedding-004`** into **ChromaDB**; the **mean embedding is the tone baseline**. Gemini (`gemini-2.0-flash`) writes a tone profile plus "lens-cleaning notes". A **LangGraph** stateful agent: chatbot node (Gemini + system instructions + example snippets), a `human_node` (shows draft, takes feedback, detects approval or exit), a `ToolNode` with `get_tone_profile`, `get_lens_cleaning_notes`, `save_post`, `evaluate_post`, a `save_node` that stores accepted posts back into ChromaDB (a **growing memory of the user's voice**), and conditional routing for the generate-evaluate-revise loop.

**Evaluation (built into the loop).** Every draft gets an **automatic tone score combining cosine similarity to the baseline embedding, drift from the baseline, and a Gemini qualitative tone rating**: a hybrid embedding + LLM-as-judge metric. No aggregate numbers reported. Interactive `input()` cells are commented out so the notebook runs top to bottom; a post-run step refreshes the tone profile from accepted posts.

### Top 10 #8: Smart Meeting Scheduler AI Agent (fareshazem)
[notebook](https://www.kaggle.com/code/fareshazem/smart-meeting-scheduler), about 2,050 words (mostly code; markdown is section summaries).

**Problem and user.** Scheduling a meeting across attendees and time zones in natural language, writing real events to **Google Calendar**.

**Design.** A **LangGraph** agent with a typed state (OAuth status, meeting details, user timezone). `ChatGoogleGenerativeAI` (**`gemini-1.5-flash`**) with `bind_tools` to two custom tools: **`find_available_slots`** (queries Google Calendar free/busy for all attendees in a window, returns common slots of the requested duration, optional timezone) and **`create_calendar_event`** (required/optional attendees, location, description). A **few-shot system prompt** sets a rule-based flow (gather info -> find slots -> authenticate -> create event) and insists on the user's detected timezone. Graph nodes handle an **out-of-band OAuth 2.0 flow** suited to Gradio (manual code entry, token pickle storage, refresh and scope checks); a router directs between scheduler, tool and auth nodes based on auth status and tool results; the graph is rendered as a Mermaid PNG.

**UI.** Gradio Blocks chat with **browser timezone auto-detection via JavaScript**. **Evaluation:** none. Notable as the winner most clearly doing real **function calling against a live external API with authentication**.

### Top 10 #9: N.I.R.A.D.: Making Research More Accessible with Generative AI (noobsajbot, Alberto Costa)
[notebook](https://www.kaggle.com/code/noobsajbot/n-i-r-a-d), about 3,400 words.

**Problem and user.** Non-experts who cannot extract usable methods from dense optimisation papers. The author, an optimisation researcher, wraps **his own two published papers on network interdiction (defender-attacker-defender models)** as agent tools, so a user can ask in plain language how to allocate a protection budget across a network (e.g. a metro) so an attacker must pay the most to cut flow. The name stands for Network Interdiction Resilience Advanced Defense.

**Design.** **smolagents** (chosen deliberately: "I figured almost everyone would have used [LangGraph/LangChain]"), with optimisation modelled in **Pyomo** and solved by **GLPK**. Typed `@tool` functions: generic network operations plus three optimisation tools (max flow, worst-case attack given an attacker budget, optimal fortification plan maximising "resilience"). The agent's LLM is **`gemini-2.0-flash`**, picked after the author's own comparison of main LLMs ("2-3 times faster response than the others", notebook claim). Few-shot examples added on top of the smolagents system prompt; **long context by concatenating prior Q&A** into the prompt.

**Image understanding with a model-choice finding.** As a bonus, the network data is extracted **from the network figure** via a `response_schema` at temperature 0; **`gemini-2.5-pro-exp-03-25` was needed because `gemini-2.0-flash` misread one arc** despite prompt changes. The extracted table matched the hand-loaded data.

**Evaluation: verification against the solver.** The agent recommends adding $4.2M to arc (4,3) and $5.8M to arc (3,5) with resilience 8.7 for a $10M budget and guaranteed flow 6; the notebook then **checks the claim**: with attacker budget 8.7 the worst-case flow stays >= 6, and at 8.8 it drops below 6 (tolerance 0.1). A small but genuine end-to-end correctness check, unusual among these winners. Interactive coloured CLI included.

### Top 10 #10: Mock Technical Interviewer with Gemini & LangGraph (maxymrim, Maksym Rimashevskyi)
[notebook](https://www.kaggle.com/code/maxymrim/mock-technical-interviewer-with-gemini-langgraph), about 6,500 words (the longest and most thoroughly documented of the top 10; each section ends with "how it solves the problems").

**Problem and user.** Job candidates preparing for coding interviews without realistic, timely, objective feedback or affordable human interviewers.

**Data.** A `data.json` gist of LeetCode-style problems (id, name, topic, difficulty, link, companies, description, starter code) loaded into pandas as the question bank.

**Design (LangGraph + `gemini-2.0-flash`).** A stateful interviewer graph. `INTERVIEWER_SYSTEM_PROMPT` sets a supportive persona at "Mock Technologie Inc.", **graduated hints (levels 1 to 3)**, "think out loud" prompting, and hard constraints: **questions must come from the database via function calling, never invented**, and the user must confirm before tools start or end the interview (both rules were added after testing showed failures, along with few-shot examples to curb "strange responses"). **Whiteboard image understanding:** candidates can upload sketches; a `DESCRIBE_IMAGE_PROMPT` converts each image to text so the final transcript is complete. After the interview, `CANDIDATE_EVALUATION_PROMPT` grades the full transcript and final code via **structured output** (Pydantic `EvaluationOutput` with strengths, areas for development, detailed analysis, final recommendation, topics to learn; `response_schema` + JSON mime type) rendered by a Jinja2 template. Then `RESOURCES_SEARCH_PROMPT` uses the **Google Search grounding tool** to build a personalised learning plan with automatic citations. Long context keeps the whole interview in view. Gradio UI (launch commented out for "Run all").

**Evaluation.** The product's output is an LLM-as-judge evaluation of the *candidate*; there is no evaluation of the interviewer agent itself. Prompt iteration was manual and qualitative.

### Honourable mention #11: OncoAssist: AI-Powered Cancer Recovery Advisor (assiaben)

### Honourable mention #15: T-AID, Technical Assistant for Industrial Docs (lguzm001, Leandro Guzmán)
[notebook](https://www.kaggle.com/code/lguzm001/technical-assistant-for-industrial-docs-t-aid/), about 5,400 words. Thesis: **"Sometimes the smartest answer is 'I don't know'."**

**Problem and user.** Maintenance staff in mining/energy/construction working from model-specific service manuals, where applying a procedure from the wrong machine's manual (different pressures, dimensions, safety steps) can damage equipment or kill someone. **Data:** public operation/maintenance/service PDFs for **Komatsu hydraulic excavators** (e.g. PC210-11, PC130-7, PC20MR-2) from all-loadermanuals.com.

**Design principle: document-level isolation before retrieval.** Embedding the whole corpus would leak context between machine models, so: (1) **offline catalog**: `analyze_document_for_catalog` uses Gemini (**`gemini-1.5-flash`**) with **function calling and few-shot prompting** to extract schema-aligned metadata per manual (type, manufacturer, model, summary, section index, technical keywords); (2) at question time `select_best_document_for_question` has Gemini pick one catalog entry **or abort if none matches**; (3) only then is that single PDF chunked and embedded (**MiniLM**, cosine top-k); (4) Gemini generates a **structured technical fact sheet** (metadata, answer with reasoning, step-by-step procedure, safety notes, referenced sections/pages).

**Evaluation (qualitative, manually built question set).** Three dimensions: document selection accuracy ("successfully identified the intended document in all tested cases where the metadata aligned"), answer grounding and structure (answers reviewed against the manuals; all stayed in-document), and **fail-safe handling** with deliberately out-of-scope questions ("Ford Model T", mismatched manufacturer-model pairs) that the system correctly refused. ## Consensus vs divergence

**Table stakes:** a single Kaggle notebook that runs top to bottom (interactive `input()`/Gradio launch cells commented out so "Run all" works, noted in SC, MI, PR), a Gemini API key from Kaggle Secrets with a retry wrapper for 429/503, at least 3 named capabilities listed explicitly in a "capabilities used" section, and blog + video. Structured JSON output and few-shot prompting appear in almost every entry because they are the cheapest capabilities to tick.

**Top 10 vs honourable mentions** (no ranks given, so only the coarse split is observable): the top 10 lean more toward **agentic tool use with real actions or real verification**: live Google Calendar writes (MS), solver-backed recommendations verified in the notebook (NI), a question bank enforced through function calling plus grounded learning plans (MI), an evaluation harness with HITL fallback (RL), a generate-evaluate-revise loop with an embedding drift metric (SC). Honourable mentions are more often single-pass RAG or prompt pipelines (OA, SP, WS, AIDER, EM), even when their documentation is longer and more careful (T-AID at 5,400 words, word2color at 10,000, PN at 6,000). Documentation length alone clearly did not decide top 10 membership.

**Divergent choices:**
- *Agent framework:* N.I.R.A.D. chose smolagents precisely because "almost everyone would have used [LangGraph/LangChain]" ([nb](https://www.kaggle.com/code/noobsajbot/n-i-r-a-d)); Mock Interviewer and Scribbles built full LangGraph graphs ([MI](https://www.kaggle.com/code/maxymrim/mock-technical-interviewer-with-gemini-langgraph), [SC](https://www.kaggle.com/code/ttuuii/scribbles-tone-aware-writing-agent)); RAGLab and the NECP engine used no agent framework at all.
- *Retrieval scope:* T-AID refuses to embed the whole corpus and first selects one manual, so context cannot leak across machine models ([nb](https://www.kaggle.com/code/lguzm001/technical-assistant-for-industrial-docs-t-aid/)); OncoAssist and EthnoMed embed everything into one Chroma collection ([OA](https://www.kaggle.com/code/assiaben/oncoassist-ai-powered-cancer-recovery-advisor)).
- *Text RAG vs structured extraction first:* the NECP engine extracts a schema into CSV and answers from the table ([nb](https://www.kaggle.com/code/kianjn/smart-policy-assistant)); most others retrieve raw text chunks.
- *Model size:* N.I.R.A.D. found 2.0 Flash both best-in-class for its agent (speed) and insufficient for diagram reading (needed 2.5 Pro); Personalized Narrator likewise split vision (1.5 Pro) from text (2.0 Flash).
