## Per-winner synthesis

### Agentic Workflow Prize 1: CaseTwin (Karthik Vemireddy, Sai Ganesh Akula, Teja Potu) — full depth
Sources: writeup, GitHub README and backend code (`arthik444/case-twin`: `main.py`, `agents.py`, `qdrant_service.py`, `embedding_service.py`, `medsiglip_inference_endpoint/handler.py`).

- **Problem and user:** a non-specialist clinician in a rural or community hospital facing an atypical chest X-ray must decide refer-or-treat and where. The team decomposes the manual baseline as ~4 hours: 30–60 min finding a similar published case, 15–20 min image comparison, 1–3 h finding the right specialist facility, 20–30 min drafting the referral; baselines are sourced to radiology-workflow and documentation-burden literature (writeup).
- **Workflow, four steps in one dashboard:** Upload → Match → Route → Memo.
  1. *Upload / intake:* an "Agentic Copilot" chat (`agenticOrchestrator.ts`) runs a multi-turn intake loop: the clinician drops images and free-text notes, **MedGemma** extracts a typed `CaseProfile` (demographics, vitals, lung findings, impression, assessment, plan), the orchestrator diffs and merges profiles turn by turn and shows a live "Profile Completeness" score, then says when the profile is complete enough to search. Gemini 2.5 Flash is used for `/enhance_profile`.
  2. *Match:* **MedSigLIP-448** (`google/medsiglip-448` behind a custom HF Inference Endpoint handler) embeds the X-ray into a **1152-dim** vector (the README says 512, the code says 1152); cosine search in **Qdrant** over a hand-curated set of **~2.2k chest X-ray cases parsed from PubMed Central case reports** with known diagnosis, treatment and outcome. Retrieval is **fused: 0.7 × normalised visual similarity + 0.3 × a rule-based clinical-context score** (age, sex, findings and keyword overlap with the CaseProfile) from `qdrant_service.py`. Full case context is embedded in every Qdrant payload so no second lookup is needed.
  3. *Compare and chat:* **MedGemma** (multimodal) receives the current and twin images plus the twin diagnosis and returns **bounding boxes `[x, y, w, h]` for the primary finding in each image** (rendered as SVG overlays) and a structured comparison (similarities, differences, progression risk, recommendations). *TwinChat* sends every question with **two contexts**, the twin's full record and the current CaseProfile. Highlighting any term triggers a 1–2 sentence MedGemma explanation.
  4. *Route (the agentic part):* `/search_hospitals` chains **You.com RAG search → Gemini 2.5 Flash enrichment (clean names, clinical rationale) → Geopy geocoding → OSRM real drive times**, with retry on a simplified query and a Gemini-generated hospital list as fallback. Selecting a hospital launches `/analyze_hospital_page`, a **CrewAI sequential crew of two agents on Gemini 2.5 Flash via LiteLLM (temperature 0.1)**: a "Medical Intelligence Researcher" with You.com search and a Jina.ai page-reader tool (renders JS hospital directories) and a "Precision Medical Data Extractor" that returns named physicians as JSON. `AbortController` cancels in-flight crews when the user switches hospitals; all runs are traced in **LangSmith**. Agent run takes 30–60 s.
  5. *Memo:* structured referral letter generated from all prior steps.
- **HAI-DEF models:** MedGemma (exact size not stated in writeup, README or code; served from an HF Inference Endpoint with a custom multimodal `handler.py` the team says they "reverse-engineered entirely from the model card") and MedSigLIP-448. Non-HAI-DEF: Gemini 2.5 Flash for routing and agents. **No fine-tuning**; the HF repo `gana96/medsiglip-448-sim` appears to be a hosting copy for the endpoint (its card is empty).
- **Deployment:** React 18 + Zustand + Leaflet SPA on nginx, FastAPI backend, both on **Google Cloud Run** (backend 2 vCPU / 2 GiB), HF endpoints **scale to zero** (2–3 min cold start); live public demo. Cloud-only; the "on-premise" story is argued (open weights allow it) rather than built.
- **Evaluation:** a time-to-decision table, ~4 h → ~5 min end to end (retrieval < 30 s, comparison < 60 s, routing 2–3 min, memo instant), where the "with CaseTwin" numbers are "measured system latency on our test dataset" (writeup). **No retrieval accuracy (e.g. top-k diagnosis match), no clinician study, no clinician on the team**.
- **Why it fits the agentic prize:** it is the one winner where agents act on the open web (search, scrape, extract) to complete a real workflow step, and the only one whose division of labour is explicit: specialist HAI-DEF models do the medical perception and reasoning, a general model runs the logistics agents.

### Agentic Workflow Prize 2: BigTB6 (Sachiv / SACHokstack, Ramaswamy / ramaswamyrama, Sidharthan / Sidharth1743; Galadon also listed) — full depth
Sources: writeup (about 1,000 words, **no metrics**), the main repo `Sidharth1743/BigTb6` README, and six component repos / HF model cards linked from the writeup; metrics below come from those READMEs, not the writeup.

- **Problem and user:** TB screening with anemia as a common comorbidity, for clinical officers in resource-constrained settings, using only a webcam and a microphone (plus an uploaded chest X-ray when one exists).
- **Agent design (why it won the agentic prize):** a **voice-first agent**. **Gemini Live** handles real-time multilingual conversation over **WebRTC through Pipecat** and uses **function calling** to decide which screening to run as the conversation unfolds. Tools: `record_cough_sound`, `analyze_cough_for_tb`, `capture_palm_photo`, `capture_eye_photo`, `capture_fingernail_photo`, `analyze_chest_xray`; capture tools grab a webcam frame and return the specialist model's analysis in the same call. A FastAPI backend fires the tool calls **asynchronously and in parallel** against independent Cloud Run microservices (e.g. cough and palm at once) to keep voice latency low. **MedGemma 4B is the "orchestration layer" in the report sense**: once modality results return, it aggregates them with webcam HR/RR into one patient-friendly report, which Gemini Live reads back as speech. So the turn-taking agent is Gemini; MedGemma is the clinical synthesiser.
- **HAI-DEF specialist models (5 services):**
  - **HeAR cough → TB:** 33k+ cough clips from a Zenodo cough corpus (record 10431329) filtered to `Permission_sound == "Yes"`, passive and forced coughs; ffmpeg → 16 kHz mono, tiled to exactly 2 s; **frozen HeAR embeddings + two domain-specific XGBoost heads** (passive, forced; 500 trees, depth 6, LR 0.03, GPU hist) averaged into one risk. **Patient-level stratified 5-fold CV** with patient labels OR-aggregated: **AUC 0.7476 ± 0.0932, accuracy 0.728 ± 0.060, sensitivity ~0.78–0.83** (repo README).
  - **MedSigLIP chest X-ray → TB:** ~11k CXRs from TBX11K, the Kaggle TB Chest X-ray set and NIH Montgomery; **linear probe / MLP probe on MedSigLIP features** with CLAHE preprocessing, **8-view test-time augmentation** and a TTA-augmented few-shot domain-adaptation step; HF `JetX-GT/hades-hellix-tb-linear-probe`. That repo also describes a MedGemma 4B-IT reasoning phase producing WHO-style screening text. No metric in the README lines checked.
  - **MedSigLIP eye (conjunctival pallor) → anemia:** ~11k images (India/Italy eye-anemia set + CP-AnemiC), linear probe with CV and threshold calibration, HF `Sidharth1743/eye-medsiglip-linear-probe`.
  - **MedSigLIP palm → anemia:** ~3k images, tuned linear probe, CV, threshold calibration, optional TTA; own Cloud Run service.
  - **Fingernail → anemia:** the writeup counts it as a MedSigLIP model, but its own HF card (`JetX-GT/nail-anemia-detector`) describes **handcrafted colour features (pallor indices, redness, haemoglobin proxies) with an MLP / ensemble**, trained on a Ghana fingernail dataset (2,725 train images, 356 patients): **AUC 0.75, accuracy 73%, recall 90%, specificity 46%**, or a 100%-recall mode at **17.1% specificity**, patient-level AUC 0.77 (README).
- **Vitals:** webcam **rPPG** (open-rppg) for heart rate, respiratory rate from spectral peaks (Welch/FFT) in the respiratory band; README flags it as "not a diagnostic tool", sensitive to light and motion.
- **"Fine-tuned" means probes:** every vision/audio model is a frozen HAI-DEF encoder plus a light head; no MedGemma fine-tuning. Weights & Biases logging in the training repos.
- **Deployment:** all five specialist models plus `medbrain-api` and `medbrain-bot` on **Google Cloud Run**; cloud-only, needs a connection for Gemini Live.
- **Evaluation:** per-component CV/test metrics in repos (above); **no end-to-end screening evaluation, no clinician validation, no latency numbers** in the writeup.
- **Contrast with CaseTwin:** both prizes went to cloud systems where **Gemini (not MedGemma) drives the agent loop** and HAI-DEF models are called as specialist tools; CaseTwin's agents act on the web (search/scrape), BigTB6's agent acts on the patient's devices (mic, camera) in real-time voice.

### Main 1st: EpiCast (Jane Odum) — bank covers in depth; new facts only
Bank has MedGemma 4B LoRA r16/α32 → merged → GGUF Q4_K_M 2.49 GB on iOS via llama.rn + Metal, MedSigLIP projector 851 MB, 3.3 GB footprint, 2–10 s offline extraction. New facts (writeup):
- **Synthetic data recipe:** 8 WHO IDSR syndrome categories × 6 languages (incl. Nigerian Pidgin, Hausa, Yoruba, Twi, French), each with symptom descriptions, ICD-10 codes and reportable flags; a generator samples syndrome, language, age, sex, severity and duration and builds a narrative from language templates, **injecting 1–2 real phrases from corpus pools** (Pidgin tweets and news, Francophone clinical questions) so the text is not "textbook Pidgin"; **9,400+ narrative → JSON pairs** (syndrome, severity, ICD-10, symptoms, WHO reportable flag).
- **Why on-device, with numbers:** RunPod serverless cold starts of 3–5 min (20 GB of models), 10–30 s per call even warm; Vertex AI needs an always-on GPU replica at $3–7/h, days of quota approval, and "vLLM and TGI kept crashing" loading MedGemma. Result: "90% of what a CHW does every day" offline.
- **Cloud side:** MedGemma **27B** weekly district situation reports and **HeAR** cough classifier on RunPod A100 (20.6 GB VRAM for 4B + 27B + HeAR + classifier). HeAR: COUGHVID (25k+ crowdsourced coughs, filtered to expert-labelled high-confidence), 2 s clips at 16 kHz → 512-dim embeddings → best of several sklearn classifiers on an 80/20 split (no metric quoted); also exported to ONNX (1.2 GB + 28.7 MB) for future on-device use.
- **Fusion and data layer:** confidence-weighted fusion of text, image and cough signals in plain JavaScript (agreement raises, disagreement lowers confidence); only structured signals sync (Supabase Postgres + pgvector, WHO epi-week aggregation trigger, offline AsyncStorage queue); dashboard alerts when a syndrome exceeds **150% of its 4-week rolling baseline**.
- **Evaluation:** **no extraction accuracy, no per-language score and no CHW or clinician validation are reported** in the writeup; the evidence offered is latency, footprint and a TestFlight build.

### Main 2nd: Sunny (Daniel and Joshua Bourke) — bank covers in depth; new facts only
Bank has MedGemma-1.5-4B fine-tuned on ~1.1k images (ISIC-2024 crops + real sunscreen photos), mlx-vlm 4-bit RTN 8.6 → 3.4 GB, Swift Transformers + MLX on iOS. New facts (writeup):
- **Labels:** **Gemini 3 Flash is the teacher** that writes the structured skin/sunscreen JSON targets (this is why the host lists Gemini-3-Flash among models used); the authors list "official inputs from professional dermatologists" as future work.
- **Training:** Hugging Face **TRL SFT**, **3 epochs on one 80 GB A100 in Colab, ~40–50 min**. Motivation shown with a before/after screen: the base quantised model fails to follow the long structured prompt; the fine-tune "adheres to structure" with the shortest total time (13.47 s vs 26.39 s and 28.44 s for prompt-only variants).
- **On-device latency:** skin extraction 3–4 s time-to-first-token and ~5–7 s total on an **iPhone 17 Pro**; sunscreen extraction 10–20 s. Future work: swap the MedSigLIP vision tower for **MobileNetV5** so it runs on the Neural Engine instead of the GPU (would need medical retraining).
- **Validation honesty:** tested only on the authors' own (lighter) skin; "a wider evaluation suite would need to be conducted"; quotes Cancer Council Australia that it does not recommend consumer self-diagnosis apps, positions Sunny as a tracking aid for discussion with a doctor. **No clinician involvement, no accuracy metric.**

### Main 3rd: FieldScreen AI (Marc Donovici, solo)
- **Problem and user:** TB screening at community camps where there is no radiologist (India ~1 per 100k people; under 1 per million across Sub-Saharan Africa, 14 countries with none) and no internet; contrasted with commercial CAD (CAD4TB hardware $15,500 + $11,475 maintenance; $0.19–2.73 per read). Claim: $0 per read (writeup).
- **Five-step offline workflow:** (1) WHO four-symptom questionnaire plus risk factors as a pre-test probability; (2) **HeAR** cough risk in < 2 s on CPU before any X-ray; (3) **MedASR** (105M; cited 5.2% vs Whisper's 28.2% WER on medical terms) for spoken CHW notes; (4) **MedGemma 1.5 4B-IT, LoRA fine-tuned, 4-bit GGUF**, reads the chest X-ray with **5-run majority voting** for stability; (5) **TranslateGemma** translates the report into 15 languages on CPU. The host also lists MedSigLIP, which here is MedGemma's own vision tower rather than a separate component (the writeup names three HAI-DEF models).
- **Fine-tuning:** LoRA rank 32, 5 epochs on **1,200 CXRs** (Montgomery County TB set plus part of the Tawsifurrahman TB database). Vision tower kept in bf16 while the language layers are 4-bit, which fixed CUDA device-side asserts when quantising vision; a **custom HF → GGUF converter mapping PaliGemma/MedGemma tensor names** because official llama.cpp scripts did not support the architecture.
- **HeAR classifier:** logistic regression on 512-dim embeddings from **Coswara** (2,150 recordings: 574 respiratory-illness positive, 1,576 healthy) as a **respiratory-illness proxy**, since no large public TB cough set is available; designed for drop-in replacement with CODA TB.
- **Evaluation (strongest in the field):** **200 held-out Tawsifurrahman images**, 5 runs each with majority vote, base vs LoRA: accuracy 84.0 → 86.0%, sensitivity 73.0 → 75.0%, specificity 95.0 → 97.0%, PPV 93.6 → 96.2%, NPV 77.9 → 79.5%, F1 0.820 → 0.843, false positives 5 → 3 (writeup). The 200-image set ships in the repo for independent verification. Caveats: same source database as part of the training data, and 75% sensitivity is low for a screening tool (the writeup emphasises specificity). No clinician validation.
- **Deployment:** Gradio app plus local `llama-server`; 4 GB VRAM (GTX 1650 class), 8 GB RAM; MedGemma ~3 GB VRAM, ~10 s per X-ray on GPU; CPU-only with `--gpu-layers 0` at ~60–90 s per X-ray on 16 GB RAM; `HF_HUB_OFFLINE=1` guarantees no network calls. Scripts: `train_image_lora.py`, `simple_lora_converter.py`, `evaluate_gguf.py`, `app.py`, one-click launchers.

### Main 4th: Tracer (Adish Golechha, solo)
- **Problem and user:** outpatient clinicians lose the "diagnostic loop": a hypothesis is formed, tests ordered, results arrive days later into a 40–80 item inbox stripped of context (illustrative case: a 1.4 cm nodule unread for 18 months). Cites 795k US deaths/disabilities a year from diagnostic error and 45% of office-based diagnostic malpractice events involving missed cancer.
- **Clinician involvement (the only main-track winner with a field survey):** a Google Form survey of **100+ respondents** (physicians, surgeons, anaesthesiologists, interns, nurses, administrators, students), Feb 2026: 83.3% had seen an unacted result, 91.7% acknowledge the gap, 0% said AI flagging would be "not useful" (writeup). Also states the 20 demo scenarios are "medically validated" (by whom is not said). Proposes a 3-month shadow-mode pilot with 10–15 physicians and ~3,000 patients.
- **Fine-tuning:** **MedGemma 1.5 4B-IT, LoRA with 4-bit bitsandbytes (QLoRA-style), prompt masking, 3 epochs on a Kaggle T4 (1 h 48 m)** on **421 hand-validated examples across 25 specialties**; val loss 1.075 → 0.866 (writeup). Adapter `adishofwhat/tracer-medgemma-v2` and Kaggle model `medgemma-loopguard-v2`; public training notebook.
- **Agentic pipeline (submitted to Agentic Workflow too, per its subtitle):** four agents: Data Validator (plausibility, rejects malformed input) → Hypothesis Extractor (the fine-tuned MedGemma) → Quality Checker (required fields, internal consistency) → Confidence Scorer (self-rated 1–10). Below 6/10 the output is flagged and the Quality Checker re-runs with an expanded prompt, a small self-correction loop. A cross-patient **Loop Tracker** lists open loops by urgency and days pending. Strictly human-in-the-loop: the model cannot suppress a result; audit trail stored.
- **Integration path:** EHR webhook on new result → fetch notes via **HL7 FHIR R4** → return enriched context; < 5 s inference; no EHR modification (Epic, Cerner, Athena pattern). Positioned as cloud SaaS, not on-device.
- **Evaluation:** an **8-model comparison on only 10 held-out notes**: completeness / valid structure / urgency accuracy. Tracer v2 100% / 100% / 90%; base MedGemma 4B zero-shot 75% / 50% / 90%; DeepSeek-R1 7B 100% / 100% / 90%; Gemma 2 2B 92% / 100% / 60%; Qwen2.5 7B and Llama 3.2 3B 0% valid structure; BioMistral 7B and Meditron 7B 0% valid structure (writeup). The writeup's lesson: medical-pretrained LLMs without task fine-tuning cannot produce the schema. Sample is tiny; percentages move in 10-point steps.
- **Demo:** Next.js 14 + Tailwind on Vercel with an AI ON/OFF toggle so judges can see before/after on 20 precomputed patients (23 open loops).

### Novel Task Prize 1: ClinicDx (Brook A)
The most ambitious fine-tuning in the field: one MedGemma checkpoint given a **new input modality (speech)** and a **trained tool-use retrieval loop**.
- **Problem and user:** clinical officers in sub-Saharan Africa on **OpenMRS** (8,000+ facilities, 40+ countries, 16.6M patients). Four gaps: clerk re-entry errors of 66–94% (Uganda study), guidelines unused as PDFs, paper lab results with 8–51 day turnaround (Ethiopia), no radiology. Delivered as one OpenMRS 3.x module with four buttons in the patient chart.
- **Voice scribe (novel task):** Phase 1, text-only LoRA (r16/α32, 1 epoch) on **180,171 phrase → FHIR observation pairs generated from the CIEL dictionary (54,653 concepts)**. Phase 2, a **projector from MedASR encoder states into MedGemma's token-embedding space**, trained **150,000 steps** with language-modelling loss plus a contrastive audio-text alignment loss; projector and LoRA merged so the model takes audio natively (bypassing ASR → text → NLP). Result on **321 held-out outpatient audio clips, 7 categories: 92% exact match, 92% F1, 94% key recall, 12.5 s per clip** (writeup).
- **Knowledge-grounded CDS with tool use:** 160+ WHO and MSF guideline PDFs compressed into a single **285 MB memvid file**, plus a 4.9 GB WikiMed index, served by a local retrieval daemon (HTTP, source attribution, relevance scores, **WHO-first then WikiMed fallback**). **5,000 synthetic traces** (OpenMRS case as XML → thinking blocks → KB queries → retrieved evidence → cited recommendation) train a LoRA **r64/α64 (131M params, 2.96%) for 2 epochs on one A100 40 GB in 66 min**, with loss masked on user and evidence turns; eval loss 0.515, token accuracy 85%. At inference an **autonomous loop of up to 6 turns** (think → query → read → think) ends in a structured assessment, considerations, actions and safety alerts with citations; the reasoning trace can be shown.
- **Imaging and OCR:** MedGemma's own SigLIP vision path, no fine-tuning (DICOM interpretation, lab-slip photo extraction).
- **Deployment:** merged `medgemma_cds_kb_v2` (4.3B params, 8.1 GB bf16, two shards) on **vLLM with an OpenAI-compatible API on one GPU next to the OpenMRS server**; offline, no cloud. Not on-device; quantised variants are future work.
- **Evaluation gaps:** voice scribe has a real held-out test; **CDS quality has no clinical evaluation** (only loss and token accuracy), imaging/OCR none; pilot deployment, GRPO and a 50k-sample CDS set listed as future work. Three videos submitted (judges watched only the first 3 minutes combined).

### Novel Task Prize 2: UniRad3s (Pon Deepika, Ghanshyam Dhamat, Pratyaksh Tandon, Ashutosh Kumar, Sandeep Kumar)
- **Problem and user:** radiologists facing backlogs, manual lesion delineation, reporting load and a patient-communication gap; proof of concept on **brain glioma MRI**.
- **Spot (triage):** classifies each 2D FLAIR slice tumour vs normal; a volume is "tumour" if **at least 4 of any 10 consecutive slices** are positive; outputs preliminary diagnosis, sigmoid confidence, the "most evident" slice (mid-slice of the detected run) and a priority queue by anomaly, acquisition time and review status. Zero-shot baseline (log-prob of tumour vs non-tumour per slice; the writeup attributes it to MedGemma in one sentence and MedSigLIP in the next) on 100 BraTS2020 + 100 OASIS-3 volumes: **FLAIR accuracy 93.5%, sensitivity 87%, precision 100%; T1ce sensitivity 92%**.
- **Fine-tuning (MedSigLIP, not MedGemma):** LoRA r16/α32/dropout 0.05 on the remaining BraTS2020 plus extra OASIS-3 healthy volumes, **SigLIP loss, 20 epochs, batch 80, LR 1e-4, grad-clip 2.0, AdamW, one RTX A5000 24 GB**. Result: **FLAIR accuracy 98.25%, sensitivity 100%, precision 96.15%, AUC 98.92** (writeup). The host's blurb says "fine-tuned MedGemma"; the writeup only describes fine-tuning MedSigLIP.
- **Segment:** the radiologist confirms the Spot slice and places **one point prompt**; **MedSAM2** segments the full 3D lesion from that prompt, enabling volume and longitudinal tracking.
- **Simplify (reporting):** MedGemma writes a clinical report from the evident slice with a bounding box from the mask, then rewrites it into a plain-language patient summary. **Anti-hallucination step (distinctive):** MedGemma initially misplaced lesions in the wrong brain regions, so the team registers an **MNI-space parcellation atlas to each subject with ANTs**, computes which regions the lesion mask touches and their volumes, and feeds these structured facts into the prompt ("parcellation-grounded" reporting).
- **Deployment:** workstation / server pipeline, Spot to Simplify in under 5 minutes; PACS integration is future work. Not on-device; not agentic.
- **Evaluation:** classification metrics above on public datasets (small, single-institution style split; healthy controls come from a different dataset than tumours, so dataset shift may inflate accuracy). No segmentation Dice, no report-quality or radiologist evaluation.

### Edge AI Prize: BridgeDx (Bibek Poudel, solo)
- **Problem and user:** community health workers and disaster first responders (motivated by the author's 2015 Nepal earthquake volunteering) who have only WHO paper flowcharts and nothing for atypical or rare presentations (e.g. visceral leishmaniasis misread as malaria).
- **Model routing:** **MedGemma 1.5 4B multimodal** (4-bit) for fast Standard Triage, including photos of wounds, skin lesions and handwritten lab results; **MedGemma 27B** (4-bit, ~20 GB RAM) for a Rare Disease Investigation mode against Orphanet; **MedASR** locally via Transformers for dictation. Below 20 GB RAM the 27B mode is disabled and everything routes to 4B ("degrades gracefully"). All via **Ollama** locally; Vertex AI optional. **No fine-tuning.**
- **Retrieval (the core):** medical-vocabulary query expansion → **hybrid BM25 + ChromaDB vector search fused with Reciprocal Rank Fusion** → **BGE cross-encoder rerank** → parent-chunk expansion; corpus 11,500+ parent chunks from WHO IMCI, MSF Clinical Guidelines 2021 + NCD 2025 (29 protocols) and Orphanet (9,000+ profiles). **Post-hoc citation verification:** every quoted excerpt is fuzzy-matched to its source and unverifiable flags are stripped before display.
- **Safety:** hard-coded vital-sign and danger-sign rules run before inference and cannot be overridden by the model; low-confidence warnings; no case is logged until the health worker confirms clinical responsibility; de-identified SQLite logs.
- **Deployment (why Edge AI):** one Docker Compose stack (React/Vite, FastAPI, MinIO, Ollama) started by a single `start.sh`, under two minutes setup, fully offline on "a $500 laptop" for the 4B path. Laptop-class edge, not phone; no latency numbers given.
- **Evaluation:** **four hand-picked scenarios** with expected diagnosis and output confidence (VL 75%, severe pneumonia 70%, Gaucher 50%, typhoid 70%); no systematic test set, no clinician review.

## Consensus vs divergence

**Table stakes.** A named, under-served user (CHWs, clinical officers, rural clinicians) with a one-paragraph statistic-dense problem statement; at least one HAI-DEF model doing a job a general model could not; working open code and a demo video; and explicit "not a diagnostic tool" / human-in-the-loop safety language.

**What separated the main-track places from the special prizes.** Every main-track winner **fine-tuned MedGemma itself** and documented it (rank, epochs, hardware), which maps straight onto Feasibility's "fine-tuning documentation". Three of four ship a **concrete deployment proof** with sizes and latency (Q4_K_M 2.49 GB on iPhone; MLX 4-bit 3.4 GB, 5–7 s on iPhone 17 Pro; GGUF on a 4 GB GTX 1650 at ~10 s); Tracer substitutes a FHIR integration path plus the only clinician survey. The top two are phone-native and offline. Special-prize winners more often skip MedGemma fine-tuning (CaseTwin, BridgeDx, BigTB6, UniRad3s) and win on one distinctive capability: a new modality (ClinicDx), segmentation (UniRad3s), web-acting or voice agents (CaseTwin, BigTB6), offline laptop deployment (BridgeDx).

**Agentic prize pattern.** Both agentic winners put **Gemini in charge of the agent loop** (CrewAI on Gemini 2.5 Flash; Gemini Live function calling) and call HAI-DEF models as specialist tools, and both are cloud-only. Agents built around MedGemma as the controller (Tracer's 4-agent chain, ClinicDx's retrieval loop, the CAP CDSS and Dual Path ICU HMs) won other awards or mentions instead.

**Contradictions:**
- *Cloud vs on-device:* EpiCast moved from RunPod to on-device after 3–5 min cold starts and vLLM/TGI crashes ([writeup](https://www.kaggle.com/competitions/med-gemma-impact-challenge/writeups/new-writeup-1770830823676)); CaseTwin accepts 2–3 min scale-to-zero cold starts on HF endpoints and still won the agentic prize ([writeup](https://www.kaggle.com/competitions/med-gemma-impact-challenge/writeups/new-writeup-1771703368723)).
- *Fine-tune vs retrieve:* Tracer shows base MedGemma 4B at 50% valid structure vs 100% after LoRA ([writeup](https://www.kaggle.com/competitions/med-gemma-impact-challenge/writeups/new-writeup-1771923230850)); BridgeDx ships unfine-tuned MedGemma and puts all reliability into hybrid RAG, reranking and post-hoc citation checks ([writeup](https://www.kaggle.com/competitions/med-gemma-impact-challenge/writeups/new-writeup-1771945306600)). ClinicDx does both (fine-tunes the model to call retrieval).
- *Cough data for TB:* FieldScreen uses Coswara as a respiratory-illness proxy and says no large public TB cough set exists; BigTB6 trains on a 33k-clip Zenodo corpus with TB labels at patient level (AUC ~0.75); EpiCast uses COUGHVID (COVID/symptomatic labels).
