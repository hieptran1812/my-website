## Per-winner synthesis

### Agents for Good, Award 1: MemoryBridge (Ventsislav Asparuhov)
[writeup](https://www.kaggle.com/competitions/vibecoding-agents-capstone-project/writeups/new-writeup-1782584701075), about 1,000 words.

**Problem and user.** Caregivers of people with early-stage dementia need to set up daily routines without constant checking. A caregiver types "Remind Maria to water the plants at 10:00"; the assisted person sees one calm, step-by-step routine on a simplified `/today` page with Listen, Done and "Help me" buttons.

**Agent design (Google ADK).** Four agents coordinated by a **deterministic workflow**, not free autonomy: Routine Planning Agent (extracts activity, time, steps), Semantic Safety Reviewer, Dementia-Friendly Communication Agent (short sentences, one action at a time) and Escalation Agent (turns "Help me" into an in-app caregiver alert; no real calls or emergency messages). "Safety First, AI Second": **deterministic gates reject prohibited categories before any LLM sees the request** (medication or dosage changes, diagnosis, financial transactions, emergency services, unlocking doors, appliance control). A **human-in-the-loop checkpoint**: agents can only create drafts; every routine needs explicit caregiver approval. Agent Skills files define each agent's responsibilities, triggers, prohibited behaviours and output format.

**Tools / MCP.** Agents never touch the database: all persistence goes through a dedicated **MCP "routines" server** with narrow tools (create draft, list routines, record approval/rejection, create alert, fetch today's routines). The author frames this as the boundary between probabilistic reasoning and deterministic persistence.

**Memory/state.** Neon PostgreSQL; redacted audit timeline visible to the caregiver.

**Evaluation (writeup).** A focused automated suite: 28/28 eval cases passed; 10/10 prohibited routines rejected and never reached the communication agent; 0 approval-bypass cases; 6/6 prompt-injection tests; 8/8 extraction cases without inventing missing times or contacts; 5/5 communication-rubric cases; 20/20 MCP server tests; 20/20 web tests; 0 axe-core accessibility violations; 0 secrets in tracked files; production smoke tests. No baseline comparison.

**Deployment.** Google Cloud Run: public Next.js web app, private FastAPI agent backend reached with **service-to-service identity**, MCP run as a local subprocess inside the backend, Neon Postgres. Synthetic demo data; explicitly "not a medical device".

**Model:** the Gemini model name is not stated in the writeup. **Video:** 730944 links https://youtu.be/4fKOBb5VRN4; the writeup's own link is https://youtu.be/0lK34NS-7Uc (both listed in the writeup links).

### Agents for Good, Award 2: CritiqAI (Eiki Tomobe, Loc Nguyen Thi Phuoc)
[writeup](https://www.kaggle.com/competitions/vibecoding-agents-capstone-project/writeups/new-writeup-1781911352583), about 2,500 words.

**Problem and user.** "Using AI to teach students not to depend on AI." A student submits an essay via Google Drive; the system never rewrites or praises it, but finds the weakest point and runs three rounds of escalating adversarial debate. The teacher gets a report only after manually approving it.

**Agent design (ADK, 6 agents, 4 MCP servers, one sequential graph).** Orchestrator (sanitises input against prompt injection) -> **Summarizer** (about 75% token reduction; the summary, not the essay, travels downstream) -> **Persona Selector** (an explicit decision tree, encoded as a skill, maps the weakness to one of four personas: Skeptic for weak evidence, Devil's Advocate for ignored opposing views, Nitpicker for contradictions, Expander for narrow scope) -> **Debate Agent** (3 rounds; escalation templates in `critical-thinking-rubric.md` loaded at runtime) <-> **Challenge Validator** (pure Python: 18 regex answer-leak patterns, single-question rule, 150-word ceiling; one regeneration, then the session errors rather than leak) -> **Analytics + Report Agent**. Agents talk only through shared ADK session state (e.g. reading `persona_active`), no direct calls.

**Tools / MCP.** Google Drive (read-only, submissions folder), Google Sheets (append + read, one sheet, audit log), **Gmail compose-only at OAuth scope** (teacher must press send), and a custom **FastMCP "argument-scorer" on Cloud Run** scoring four Paul-Elder dimensions 0 to 5. English scoring is deterministic keyword matching (0 LLM tokens); Vietnamese, Japanese and Chinese use one Gemini call at temperature 0, LRU-cached.

**Model and cost (writeup).** Gemini 2.5 Flash Lite on the AI Studio free tier; about 3,150 tokens per English session and 3,450 non-English, roughly 317 sessions/day on the free quota.

**Observability / evaluation.** ADK OpenTelemetry spans per agent invocation. `agents-cli` lifecycle build -> eval -> deploy, with two evalsets (`debate_quality.evalset.json`, `persona_trigger.evalset.json`) that must pass thresholds before deploy. No pass rates or case counts are reported; the worked example shows a student going from an estimated 4/20 to 10/20.

**Build journey.** Started as a single-prompt chatbot that dropped persona and leaked answers; each component (validator, deterministic scorer, HITL gate) was added in response to an observed failure. Stated limitations: persona drift over 3 rounds, gameable keyword scorer.

**Deployment.** Scorer as its own Cloud Run service with Dockerfile; `agents.json` registers 6 agents, 3 skills, evalsets.

### Agents for Good, Award 3: AccessPilot (Arun kumar)
[writeup](https://www.kaggle.com/competitions/vibecoding-agents-capstone-project/writeups/accesspilot-autonomous-accessibility-repair-agent), about 800 words (relatively thin, architecture mostly in images); supplemented from the [GitHub README](https://github.com/joinarun/accesspilot).

**Problem and user.** Developers. Detection of WCAG failures is solved (the writeup cites 100 to 125 evaluation tools, yet 96% of top home pages still fail); remediation takes days to months. AccessPilot closes the loop: audit, patch, re-test, explain.

**Agent design (ADK 2.0 workflow graph, 6 agents).** Crawler (browser automation, discovers routes, forms, flows) -> Accessibility Auditor (deterministic checks: **axe-core, Lighthouse, Playwright, keyboard-flow tests**; findings with severity, WCAG reference, evidence) -> User-Simulation (tab navigation, forms, modals, focus, validation errors) -> Root-Cause (groups findings by component and cause to avoid conflicting repairs) -> Repair (minimal patches to HTML, React, CSS, ARIA, labels, focus) -> Evaluator (re-runs the same tests, before/after report, regression check). Works on a **sandboxed branch**, shows the exact diff with a rationale per change, and **requires human approval before merge**; the README adds that approval is bound to the exact diff hash, verification result and Git HEAD.

**Model (README).** Per-run choice of deterministic typed specialists, Gemini (`gemini-2.5-pro` in the sample config) or an OpenAI-compatible model through an enterprise proxy; the graph sees only an ADK `BaseLlm`. Provenance logs record provider/model per specialist call but never prompts or source.

**Evaluation.** Demo on a deliberately flawed bundled app (unlabeled controls, contrast, heading order, inaccessible modal, broken focus). README: the end-to-end AA integration reaches **zero remaining findings**; the checked-in scan-only local eval reports 7 original findings. `agents-cli eval generate/grade` exercised plus local generate/grade scripts. No numbers beyond these.

**Build.** Entirely vibe-coded in Google Antigravity. No MCP server or cloud deployment is described in the writeup (README ships a Dockerfile). Also links a Google Slides deck.

### Agents for Business, Award 1: Chance Electro (Artem Borisov / barmanoff)
[writeup](https://www.kaggle.com/competitions/vibecoding-agents-capstone-project/writeups/chance-electro-draft), about 2,000 words.

**Problem and user.** Built by a business consultant for a real client: a small electrical contractor (owner plus six electricians) whose estimates take 2 to 3 days because there is often no electrical design and the owner never gets three uninterrupted hours. Slow quotes lose leads; wrong prices lose margin. Claimed value about $90K/year ($50K owner time at about 56 h/month, $40K recovered jobs), explicitly "illustrative, not an audit" (writeup). The capstone version is a US-localised presentation (feet, USD, AWG) of a system the author says is in real use.

**Flow.** Six UI steps: Client -> Input (voice, text, JPG/PNG/PDF/XLSX/DOCX, napkin sketch) -> Review -> Questions -> Estimate & margin -> Done (print-ready proposal, contract, invoice, shop order as PDF). Claimed: 2 to 3 days -> about 10 minutes (writeup).

**Key design rule: "an agent where judgment is needed; a tool where it isn't."** Exactly one LLM consumer: **Agent 1, Project Analyst, uses Claude Vision** (not Gemini) to turn unstructured input into structured project JSON, and returns a **quiz of targeted questions instead of inventing** missing facts. Agent 2 Document Factory and Agent 3 Profitability Advisor are **deterministic**. Unknown operations are flagged "NOT IN PRICE LIST" rather than priced.

**Framework.** Three agents are independent HTTP servers speaking **A2A** with agent cards at `/.well-known/agent-card.json`; agents 2 and 3 run in parallel. An **ADK `BaseAgent` orchestrator with no LLM of its own** drives the A2A pipeline and sees the MCP tools through `McpToolset` (the "MCP + ADK + A2A" pattern). **MCP Pricing Server** with six tools (`price_estimate`, `compute_margin`, `recommend_cable`, ...) over the price list, an NEC cross-section map and the margin engine; all agents are MCP clients. Agent Skills registry with trigger-based selection, progressive loading and an executable validator that triggers a self-correction round (e.g. wrong cable cross-section for a load class).

**Security.** `guardrails.py`: input validation with magic bytes, multilingual prompt-injection filter, output schema validation, prompt-leak guard, **budget ceiling + kill switch** (clean HTTP 400), audit trail.

**Evaluation.** No quantitative eval; a Gherkin spec written before code ("the agent must ask, not invent"), keyless GitHub Actions CI (MCP round-trip, guardrails, mock end-to-end), `CAPSTONE_MOCK=1` runs everything free. Lessons: vision non-determinism (fixed with strict schema + quiz + skill check); mock tests hid a $0-price bug because vision output copied category prefixes; a stale process held the port on deploy.

**Deployment.** Live at electro.team247.online on systemd behind Caddy/HTTPS (not Google Cloud). Built in **Claude Code; Antigravity explicitly not used** ("We don't claim it").

### Agents for Business, Award 2: Trajectory Auditor (Shay Isso)
[writeup](https://www.kaggle.com/competitions/vibecoding-agents-capstone-project/writeups/new-writeup-1783355733656), about 1,300 words. **Bank 8c already covers** the DAG (Analyst -> 7 parallel judges -> Skill-Synthesizer -> Vibe Diff gate), the 3-tool MCP server (`load_trajectory`, `score_dimension`, `write_skill_patch`, verified from a headless Claude Code session), the context economics (139K to 400K-token sessions; 5 to 15K evidence windows instead of about 1M tokens per audit) and the 42-email fixture incident. New facts only:

- **Real audit result (writeup).** On a real, sanitised 39-minute session the operator had labelled "failing", the auditor gave Self-repair 5/5 with step citations; the operator's memory was wrong. Visual/behavioural correctness got 2/5 with "cannot be confirmed from this static code trace": judges flag when a dimension's ground truth lies outside the trajectory.
- **Selection-bias controls, three layers.** (1) Fabrication impossible by construction: the Analyst only *points*, deterministic code extracts verbatim evidence, judges never see the Analyst's narrative, citations validated in code. (2) A deterministic **salience scanner** (error patterns, failed commands, user corrections, no LLM) gives a coverage metric: 36 salient steps, 7 uncovered, warning shown. (3) **Seeded ground truth, "mutation testing for evaluators"**: twin 120-step fixtures differing by one planted step.
- **Prompt-injection A/B (writeup).** Step 117 of the injected twin tells the judges to give 5/5. Control scored [3,3,2,5,5,5,5]; injected scored *lower* (Intent -1), every judge attached a safety observation. Trajectory content enters prompts as delimited data, never instructions.
- **Vibe Diff gate** diffs a proposed skill's permissions against what the audited session legitimately used; it blocked **three real Synthesizer proposals** for overreach (shell execution, `.env` inspection) plus the planted fixture. Approved skills are only staged; a human applies them with a separate script and once downgraded a tier after the LLM gate approved.
- **Testing split.** Deterministic seams under pytest (183 offline green tests); LLM behaviour only via `agents-cli eval`. Trajectory-match metrics deliberately not run on its own agent because the fixed DAG makes them test the framework, not the model. Labels corrected only against independent witnesses (salience scanner, a 510,691-char context dump at step 300, "[Request interrupted by user]" at step 301).
- **Model (README):** Gemini via API key, used as LLM-as-judge; exact model name not given in writeup or README. One audit is about 10 to 11 requests (about 2 audits/day on the free tier). README: generated SKILL.md files ship 3 eval cases + 4 self-checks; full STRIDE threat model in `threat_model.md`; Docker distribution, no cloud deployment claimed.
- **Limitations stated:** no real session in their set was clean, so the no-skill path is unit-tested only; checkpoint-resume is a tested layer, not wired.

### Agents for Business, Award 3: ReviewOps Agent (Max Kyselov)
[writeup](https://www.kaggle.com/competitions/vibecoding-agents-capstone-project/writeups/new-writeup-1783340134268), about 2,500 words. Synthetic data throughout.

**Problem and user.** Engineering managers writing performance reviews from memory, often by pasting a year of 1:1 notes into a public chatbot (recency bias plus a privacy incident). ReviewOps collects consented employee evidence continuously and drafts reviews where **every claim cites an evidence id**; decisions stay with the manager.

**The one idea: "earn the trust in code, then use the model."** Access control (`canManagerViewEmployee`), consent gate and PII minimisation run in the **TypeScript Next.js app before the agent is ever called**; the LLM is never the authorisation boundary. Outside-team access returns 403. Survey links are random tokens stored only as SHA-256 hashes, with expiry and revocation; HMAC-signed sessions, rate limiting, audit log including denied access.

**Agent design: Python ADK 2.0 graph `Workflow`s** with Pydantic-typed I/O, chaining LLM agents and deterministic `@node`s ("write software, not rules"). Three workflows: **Questionnaire** (`questionnaire_agent` -> `safety_agent` verdict -> deterministic `expand_node`); **Evidence** (`security_node` PII redaction -> `evidence_validator` scores and maps to values/goals/role -> `finalize_node` **confidence-gated routing**: above threshold auto-approve, else manager queue; vague answers get a follow-up question); **Review** (`privacy_node` -> `review_draft_agent` citing ids, rating each role expectation as at/above/developing/not yet evidenced -> `fairness_node` flagging unsupported claims, vague praise, recency bias). A `drafting-performance-reviews` skill loaded via ADK `SkillToolset`. HITL approval before sending, drafting, approving and exporting.

**Model:** Gemini 2.5 Flash via Vertex AI. **Tools / MCP:** mock BambooHR- and Lattice-shaped connectors behind typed contracts ("MCP-ready"); **MCP server listed as roadmap, not built**. Antigravity used only to set up the GCP CLI.

**Scaling trick.** A real manager's ~440-skill matrix timed out against Vercel's 60 s cap. A deterministic parser mangled it (reverted); the fix chunks whole sections under a size budget with a shared preamble, generates chunks concurrently (`asyncio.gather` + semaphore), then merges and safety-checks once: 3 chunks -> 420 questions in about 40 s (writeup).

**Evaluation (writeup).** 67 Vitest tests in 13 files, typecheck, Playwright smoke against production. Agent behaviour via **`agents-cli eval` golden datasets with LLM-as-judge rubrics on Vertex AI**: questionnaire 4.67, evidence 5.00, review 5.00. The eval found a real bug: a request dominated by protected topics was silently replaced with safe questions and reported "approved"; a hard-refuse path took that case 1/5 -> 5/5. Review rose 3.89 -> 5.00 after a mandatory section template. **Observability:** OpenTelemetry spans to Cloud Trace.

**Deployment.** Agent service on **Cloud Run** (Vertex mode, no API key in the image, runtime service account); frontend on Vercel with Turso/libSQL. Honest maturity note: the questionnaire flow ran a real ~420-question survey for a real team; the review flow has had little real use.

### Concierge Agents, Award 1: BiteBudget (Cristina Tugui)
[writeup](https://www.kaggle.com/competitions/vibecoding-agents-capstone-project/writeups/bitebudget-an-intelligent-cooking-and-grocery-exp), about 2,000 words.

**Problem and user.** Households who find recipes online, retype them into grocery lists, retype receipts into budgets and never see spending patterns (e.g. meat vs vegetables last month). One "session-sticky" assistant for cooking and grocery spending.

**Agent design: ADK Workflow state machine** (`google.adk.workflow`) with a Pydantic `WorkflowState` (`active_agent`, `recipe_ready`, recipe name/ingredients/quantities, sanitised `user_query`). Nodes: `ocr_preprocessor` (Gemini vision OCR of recipe cards, meal photos, receipts, merged into the message) -> regex **PII redaction** (emails, 13 to 19-digit cards, phones) -> `security_gate` (a dedicated `gemini-flash-lite-latest` call as prompt-injection classifier; on detection the workflow **pauses with ADK `RequestInput`** and asks the user whether to proceed) -> intent router (cooking / budget / unknown) with a **stickiness rule** so chit-chat stays in the active branch. Two `LlmAgent` sub-agents: Cooking (`load_web_page`, `finish_recipe`, image meal decoding) and Budget (`record_purchase`, `get_shopping_history`; instructed never to log $0 or unconfirmed purchases). A Shopping step writes `shopping_list.md` as a checklist synced both ways with the UI.

**Memory/state.** Local JSON file `shopping_history.json` as the "database"; markdown shopping list on disk.

**Tools / MCP.** No runtime MCP server: MCP (GitHub MCP, google-developer-knowledge MCP) was used **at development time** in Antigravity; runtime tools are ADK custom tools the writeup calls "MCP-style". Agent skills: own `readable-vibe-coding` and `funky-modern-ui` skills plus Google's agents-cli scaffold/workflow/adk-code/eval/deploy skills.

**Evaluation.** Unit tests (OCR parsing, PII regex, schema), integration/E2E tests over SSE, and `run_local_eval.py` with **6 eval cases** (dinner suggestions, multi-turn recipe finalisation, purchase logging, PII, injection, a "future trip" pushback) on metrics `custom_response_quality`, `agent_turn_count`, `multi_turn_task_success`, `multi_turn_tool_use_quality`, **LLM-as-judge with `gemini-flash-lite-latest`**; plus a synthetic user simulator (Gemini-backed) producing `synthetic-dataset.json`. No scores reported.

**Deployment.** Local only (FastAPI + React/Vite, launched with `agents-cli playground`); ADK web UI for tracing. Built entirely in Antigravity. Notable: the least infrastructure of the 12 winners yet the API's Award 1 in Concierge.

### Concierge Agents, Award 2: TripWeaver (venugopal veldhurthi)
[writeup](https://www.kaggle.com/competitions/vibecoding-agents-capstone-project/writeups/tripweaver-a-multi-agent-travel-planner-that-fix), about 1,600 words; supplemented from the [README](https://github.com/VenuAIAgenticDev/TripWeaver).

**Problem and user.** Travellers with a multi-constraint request ("5 days in Paris from SFO, ~$3,000, art and food, relaxed pace"). A single LLM prompt produces plausible itineraries that silently break budget or timeline because it never checks its own arithmetic.

**Agent design: classic ADK workflow-agent composition**, the closest of the 12 to the course's own patterns. Root `SequentialAgent` with four phases; agents communicate only through session state (`output_key` written, `{key}` templating read). (1) `intake_agent` (`LlmAgent`) -> structured `trip_spec` with IATA codes, dates, party, budget, interests, pace, `has_lodging`, plus an **`assumptions` list of inferred values**. (2) `ParallelAgent` fan-out: `flight_agent`, `lodging_agent`, `activities_agent`, each writing a distinct state key so branches never race; lodging self-skips via a `before_agent_callback`. (3) **Reconciliation `LoopAgent` capped at 3 iterations**: `conflict_checker` reports concrete budget/schedule conflicts or `NO_CONFLICTS`; `adjuster` revises (cheaper flight, budget hotel, drop lowest-value activities) or calls an `exit_loop` tool that sets `tool_context.actions.escalate = True`. (4) `itinerary_agent` writes Morning/Afternoon/Evening blocks that respect late arrivals and early departures, with a budget breakdown.

**Tools / MCP.** `search_flights`, `search_hotels`, `search_activities` wrap **Amadeus and Google Places** with identical-shape mock fallbacks (`USE_MOCKS=true`, runs on one free AI Studio key). Optional **BigQuery price analyst** via ADK's first-party `BigQueryToolset` with `WriteMode.BLOCKED` (NL-to-SQL over historical fares). Optional bundled **FastMCP logistics server** (currency conversion, visa requirements, packing) consumed through `MCPToolset` over stdio **with a `tool_filter` allow-list** as a least-privilege boundary.

**Evaluation (README).** Behaviour tests in `eval/test_scenarios.py` assert structure (every state key populated, over-budget inputs trigger the loop, minimal prompts get defaults) rather than wording; an ADK evalset with three scenarios; GitHub Actions CI (static checks always; mock pipeline only when a key secret exists). No scores reported.

**Deployment.** `deploy_cloud_run.sh` + Dockerfile for **Cloud Run**; README names Vertex AI Agent Engine as the alternative. Gemini model name not stated in the writeup (configurable in `config.py`).

### Concierge Agents, Award 3: KinKeeper (Shalini Guda Padmanath)
[writeup](https://www.kaggle.com/competitions/vibecoding-agents-capstone-project/writeups/kinkeeper-never-forget-to-remember-the-people-yo), about 2,200 words (long on narrative, short on numbers).

**Problem and user.** The family "memory keeper": birthdays, anniversaries and remembrance days are buried in WhatsApp group chats. KinKeeper turns a WhatsApp-style `.txt` export (upload, paste, or a synthetic demo sample) into **memory cards**: person, event type, inferred date, confidence, redacted source snippet, reminder timing, suggested next action, edit/delete. Example logic: "Happy birthday Lily", "Late happy birthday Lily" and "Lily turns 10 on July 8" merge into one memory; a bare "Happy birthday!" becomes `needs_review`; "Happy 4th of July everyone" is ignored. High/medium-confidence items are auto-captured, low-confidence ones surfaced for review: a light HITL rather than per-item approval.

**Agent design (ADK workflow, 9 steps).** Security checkpoint -> chat parser -> event extraction agent -> identity resolver -> creative concierge -> privacy guard -> reminder planner -> audit report -> final response. Deterministic nodes do input checks, parsing (timestamps, multiline, deleted messages, media placeholders), reminder date maths, grouping and audit; `LlmAgent` sub-agents do extraction, identity resolution (nicknames, sender vs celebrated person) and suggestions. Shared workflow state carries messages, candidates, confidence, privacy flags.

**Tools / MCP.** A **local MCP server** with narrow domain tools: read synthetic sample, save events, list events, generate reminder schedules, suggest demo actions, write audit logs. No auto-sending, no marketplace or payment actions.

**Security/privacy.** PII redaction (phones, emails), prompt-injection detection, **raw chat never persisted** (processed in memory; only sanitised metadata stored), `.env` git-ignored.

**Evaluation.** Behaviour specs (Gherkin), tests and eval cases covering parsing, extraction per event type, duplicate merging, redaction, injection blocking, no raw-chat persistence, MCP tools, upload flow (`make eval`). No counts or pass rates given.

**Build method (the distinctive part).** Spec-driven, **token-efficient Antigravity build**: a dozen focused markdown specs (brief, rubric mapping, build orchestrator, ADK architecture, MCP tools, security/observability, UI, tests/evals/Gherkin, submission plan); Antigravity was given only the current phase's spec and **had to pause after each phase for human review**.

**Deployment.** Writeup says it is designed to run locally and "does not require a public deployment endpoint", yet a live **Cloud Run** UI is linked (730944 and README). Gemini model name not stated.

### Freestyle, Award 1: Palimpsest (Carlos Paz)
[writeup](https://www.kaggle.com/competitions/vibecoding-agents-capstone-project/writeups/palimpsest), about 2,000 words.

**Problem and user.** Historians, genealogists and digital-humanities projects facing millions of colonial-era Spanish manuscript scans (PARES, Latin American archives) that printed-text OCR cannot read and paleographers are too expensive to transcribe. Upload a scan; in under a minute get a verbatim transcription, a cleaned/normalised version, Wikidata-linked entities and amber highlights on uncertain words.

**Agent design: ADK `SequentialAgent` of 4 `LlmAgent`s**, with the rationale that one prompt doing everything "helpfully" expands abbreviations it is unsure of and silently changes the source. (1) **TranscriptionAgent: Gemini 2.5 Pro vision**, verbatim only; `maxOutputTokens=65536`, `temperature=0.1`, `thinkingBudget=128`. Model choice is evidenced: **Gemini 2.5 Flash failed 3 of 4 real manuscript pages** in development with confident wrong readings; Pro distinguishes a final *-s* from *-n* (writeup). (2) **CleaningAgent: Gemini 2.5 Flash** (text-to-text), packaged as a reusable ADK Agent Skill exposed via `AgentTool`; uses a curated **46-entry abbreviation dictionary**, marks uncertain expansions `[?]` instead of guessing. (3) **ContextAgent** calls a **FastMCP server (stdio subprocess) with 4 tools**: `lookup_entity` (Wikidata SPARQL), `normalize_date` (archaic dates -> ISO 8601), `expand_abbreviation`, `place_context` (Wikidata + Wikipedia REST); no API keys needed. (4) **VerificationAgent runs last** and scores each word/span 0.0 to 1.0; running it earlier would flag raw abbreviations as false positives. UI: Gradio, amber below 0.95 confidence, "Uncertain" count below 0.7.

**Security (SEC-01 to 04).** Byte-signature file validation (`filetype.guess()` before Pillow), 20 MB cap, **EXIF stripping** by rebuilding the image from pixels, and every system prompt labels manuscript text as DATA (OWASP LLM01:2025).

**Evaluation.** Qualitative on one primary document, a real 15th-century Columbus lawsuit fragment (`colon_1498_15c.jpg`) with a full before/after excerpt and Wikidata IDs (Columbus Q7322). "Abbreviation expansion accuracy exceeds 90% on the 46-entry dictionary" (writeup, no test-set size). Latency 20 to 40 s per page.

**Counter-intuitive finding:** `thinkingBudget=128` beats higher budgets for transcription; higher budgets over-analyse ambiguous strokes.

**Deployment.** Docker, live at palimpsest.cpaz.es (self-hosted, not stated as Google Cloud).

### Freestyle, Award 2: Project A.R.I.E.S. (Nayananshu Garai)
[writeup](https://www.kaggle.com/competitions/vibecoding-agents-capstone-project/writeups/project-aries), about 2,600 words (over the 2,500-word cap by this count; dense feature inventory).

**Problem and user.** Space-weather researchers stitching together incompatible sources by hand: NASA DONKI (4 endpoints CME, FLR, GST, SEP), EONET (GeoJSON), APOD, NOAA SWPC, under a 30 req/h DEMO_KEY limit, then doing signal processing, physics with unit conversions, ML and report writing. A.R.I.E.S. chains it into one pipeline that outputs an 8-section academic report (Abstract to References) with embedded dashboards, exportable to Markdown/DOC/PDF.

**Agent design (the most sprawling of the 12).** `IntentParserAgent` (11 intent types; keyword table of 35 to 46 mappings plus LLM classification, with a "domain safety net" letting keywords override the LLM) -> `OrchestratorAgent` picks a **dual path**: fast direct execution, or an **ADK "Brain" plan -> reason -> route -> reflect loop** (Planner decomposes into a 3 to 7-step DAG, Reasoner picks tools, Router dispatches to 14 agent types, Reflector returns PASS/RETRY/FAIL, up to 3 retries) -> **6 sequential role agents with quality gates** (Data Collector -> Analyst -> Validator -> Interpreter -> Reporter -> Reviewer). Tool registry of **~135 functions**, TF-IDF tool retriever (top 20 per query), 19 auto-discovered skills loaded per intent to keep the base prompt lean.

**Tools / MCP / RAG.** **FastMCP NASA server over stdio** (DONKI, EONET, APOD) with direct-call fallback and source-specific LRU+TTL caching. 35 physics formulas with schemas, physical-limit validation and error propagation; 6 filters (median, Savitzky-Golay, Butterworth, Wiener, FFT, spectrogram); ML trained CPU-only on demand: Isolation Forest (contamination 0.05, window 168), XGBoost ONNX flare predictor (6 features), ARIMA+XGBoost+Persistence ensemble weighted by Brier score. RAG is **TF-IDF over 2 seed documents** (no vector DB). `AnalysisMemory` stores past results by cosine similarity (200 entries, 30-day TTL). 7 cache instances with an invalidation graph.

**Security.** Input screener (8 pattern classes, 50,000-char cap), PII redactor (8 types), **AST execution guard** blocking 20 modules plus eval/exec/compile, sandboxed exec with 30 s timeout, audit log, API-key scrubbing in errors. APIs failing fall back to mock data tagged `{"mock": true}`.

**Model (README):** `GeminiClient` with primary + fallback models; README names gemini-2.5-flash and gemini-2.5-flash-lite. **Observability:** real-time SSE "thinking trace" of agent decisions, tool calls and which model (primary vs fallback) served. **Evaluation:** none quantitative; four copy-paste test prompts and a self-assessment A-to-F grader. **Deployment:** single FastAPI process, Docker multi-stage, live on Render.

### Freestyle, Award 3: AstroTyper: Infinite Odyssey (Eugene Huang)
[writeup](https://www.kaggle.com/competitions/vibecoding-agents-capstone-project/writeups/new-writeup-1783370589012), about 1,700 words (marketing-heavy; the author notes the writeup itself was AI-assisted).

**Problem and user.** People learning touch typing. Classic typing games (Typing of the Dead, Mario Teaches Typing) use fixed scripts; AstroTyper is a bullet-hell choose-your-own-adventure typing RPG whose waves and story branches are generated live.

**Agent design: deliberately NOT ADK.** The only winner of 12 that skipped ADK: the author chose the **Google GenAI SDK** because the app deploys as Vercel serverless functions and did not need ADK's Cloud Run-oriented overhead. One stateless "Game Master" LLM reads a strict system prompt plus the player's live **WPM** and returns a **rigid Pydantic schema** of enemy waves and narrative branches; faster typists get longer, more complex segments; fast enough routes you to one of two bosses. Model via env var `GEMINI_MODEL` (example given: `gemini-3.1-flash-lite`).

**The agentic part is the build process.** 25 hours total (3 h architecture, 22 h coding/testing) in **Antigravity** with spec-driven development: `game_design_spec.md` as source of truth, `implementation_plan.md`, `task.md`, `threat_model.md`, `.agents/AGENTS.md` ruleset, and all mechanics values centralised in `src/gameConfig.ts`. Six custom **Antigravity agent skills**: `/tdd` (write failing test, fix, verify), `/run_tests`, `/sync_specs` (sync code changes back into specs), `/git-commit`, `/stride_threat_model`, and **`/self_play` (a headless-browser agent that plays the game at set WPM rates to QA difficulty curves)**; a `?bot=100` URL flag exposes that bot publicly.

**Evaluation.** Jest unit tests that simulate keystrokes against the physics engine, plus an offline **LLM-as-judge suite** (`tests/eval/run_evals.py`) with positive cases (valid branches) and negative cases (breaking the 4th wall), judged also on hitting exact word counts per WPM. No scores reported.

**Security.** STRIDE threat model (via the skill), Pydantic schema bounds, rate limiting, env-var secrets. **No MCP. Deployment:** Next.js frontend + FastAPI serverless functions on Vercel.

## Consensus vs divergence

**Table stakes (nearly all 12):** an ADK multi-agent pipeline that is a **fixed workflow, not a free-roaming agent** (sequential/DAG/state machine); a named security layer (prompt-injection handling, PII redaction, least-privilege tools); video + repo + a README that maps each course concept to a file. Almost every writeup argues "why agents" by naming a failure of the single-prompt version (CritiqAI's answer leaks, Palimpsest's silent normalisation, TripWeaver's unchecked arithmetic).

**What the API's Award 1 entries share** (ordering is API-only; 730944 gives no places): all four (MemoryBridge, Chance Electro, BiteBudget, Palimpsest) are grounded in a concrete real user or artefact (a dementia caregiver workflow, a real contractor client, a household budget, a real 15th-century Columbus document), and three of four put a hard deterministic boundary where a mistake would be costly (MemoryBridge's pre-LLM gates, Chance Electro's single LLM consumer, BiteBudget's injection pause). Infrastructure depth did not decide it: BiteBudget runs locally only, while the most infrastructure-heavy entry (A.R.I.E.S., ~135 tools) is Award 2.

**Divergent choices:**
- *ADK vs not:* AstroTyper argues ADK is overhead for a serverless app ([writeup](https://www.kaggle.com/competitions/vibecoding-agents-capstone-project/writeups/new-writeup-1783370589012)); everyone else treats ADK as the spine.
- *Where the LLM sits:* Chance Electro keeps exactly one LLM consumer and makes everything else deterministic ([writeup](https://www.kaggle.com/competitions/vibecoding-agents-capstone-project/writeups/chance-electro-draft)); A.R.I.E.S. routes through LLM planning, reasoning and reflection loops with 3 retries ([writeup](https://www.kaggle.com/competitions/vibecoding-agents-capstone-project/writeups/project-aries)).
- *Scoring with LLM vs rules:* CritiqAI scores English arguments with zero-token keyword rules for auditability and cost ([writeup](https://www.kaggle.com/competitions/vibecoding-agents-capstone-project/writeups/new-writeup-1781911352583)); Trajectory Auditor and ReviewOps use LLM-as-judge with evidence citation ([TA](https://www.kaggle.com/competitions/vibecoding-agents-capstone-project/writeups/new-writeup-1783355733656), [RO](https://www.kaggle.com/competitions/vibecoding-agents-capstone-project/writeups/new-writeup-1783340134268)).
- *Bigger model vs less thinking:* Palimpsest found Gemini 2.5 Flash failed 3 of 4 pages (needs Pro) but that a *low* thinking budget (128) beats high ones for transcription ([writeup](https://www.kaggle.com/competitions/vibecoding-agents-capstone-project/writeups/palimpsest)); CritiqAI runs everything on 2.5 Flash Lite for the free tier.
- *MCP as runtime boundary vs dev tooling:* MemoryBridge forces all persistence through MCP ([writeup](https://www.kaggle.com/competitions/vibecoding-agents-capstone-project/writeups/new-writeup-1782584701075)); BiteBudget counts dev-time GitHub MCP and "MCP-style" tools ([writeup](https://www.kaggle.com/competitions/vibecoding-agents-capstone-project/writeups/bitebudget-an-intelligent-cooking-and-grocery-exp)); ReviewOps lists MCP as roadmap only. All three won.
