## Per-winner synthesis

### Main 1st: GEM-4, Gemma Embodied 4 Physical Assistance (takaki-maeda + 4)
Sources: writeup plus repo READMEs (github.com/takaki-maeda-99/GEM-4 and its `GEM-4-VLA/` subproject), which carry the numbers the writeup shows only as images.

**Problem and user.** A wearable robot arm as a "second arm" for people with visual or upper-limb impairments, for small unpredictable actions (pull out a chair, take an item off a shelf, pick up a dropped object, hold a container). Wearability means a shifting first-person viewpoint, limited reach, operation near the body and a model small enough for local execution.

**Model.** A VLA: **SigLIP + Gemma 4 E2B backbone + per-domain input/output projectors + an L1-regressed action head**. The action adapter cross-attends over the hidden states of *every* Gemma 4 layer. Gemma 4 is **frozen**; only projectors and the action head are trained. Domain-specific projectors are swapped per robot dataset to learn embodiment-independent representations.

**Training.** Pretrain on 9 Open-X-Embodiment datasets + the LIBERO 4-suite mix at ~8:2 for 100k steps (`takaki99/GEM-4-Pretrained-OXE`), then fine-tune per LIBERO suite and on their own real-robot data. FT recipe: batch 8 × 2 GPUs × accum 2 = effective 32 (spatial/object/goal), 8 × 4 GPUs × accum 4 = 128 (libero_10). Compute: a GPU server at Toyota Technological Institute (Ukita Lab), public data plus own demos only. Checkpoint ~11.7 GB.

**Evaluation (the strongest benchmark among all 14 winners).** LIBERO at FT step 50k, 100 episodes per suite, headless MuJoCo: **spatial 72%, object 92%, goal 89%, long (LIBERO-10) 43%, average 74%** (README). All four FT checkpoints are on Hugging Face with eval configs, so results are reproducible without training. No comparison to a published VLA baseline (OpenVLA, pi0 etc.) is given. The team names LIBERO-Long as the weakness.

**Data infrastructure.** *MimicRec*: data collection, visualisation, upload and inference UI abstracted across robots via per-robot control adapters. *MimicAnno*: (a) subtask segmentation from gripper open/close events, end-effector velocity/acceleration and action-norm changes (gripper is the strongest signal), each segment tracked with **SAM3** and labelled by **a Gemma 4 QLoRA-finetuned with Unsloth** (verb, object, target, confidence; e.g. approach_object → grasp → move_to_target → place_object → retreat); (b) end-effector estimation from GoPro Hero 11 first-person video with MediaPipe hand landmarks + UniDAC metric depth, giving wrist position, yaw/pitch/roll and pinch distance, in a shared format so human video can become labelled robot data. The host summary says the labeller is **Gemma 4 31B**; the writeup and README say only "Gemma 4" QLoRA via Unsloth (size not stated in the text read).

**Deployment.** Raspberry Pi 5 client ("hey GEM" wake word or GPIO) captures chest/wrist camera frames and mic audio; audio goes to `faster-whisper` on a **Jetson AGX Orin 32 GB** ($1,449), text plus images plus joint state go to the VLA `/predict` server on the Jetson; RealSense D435i wrist camera; no cloud. No latency or control-rate numbers; quantisation listed as future work. Five videos.

**Positioning.** Explicitly a research prototype, not a medical or certified assistive device; single-user hardware fit, no cross-embodiment validation yet.

### Main 2nd: Trido, a voice-driven AI whiteboard (DuoDol: Ardelyo, Azhar Ayatullah)
**Problem and user.** One named user: Pak Damar (Dadan Mochammad Ramdhan), a Bahasa Indonesia teacher in Bandung with physical disabilities in both hands and legs. Framing: Indonesia's 3 million teachers face physical, equipment, internet or language limits. He tested it in real classes for six weeks.

**Product.** A voice-first infinite-canvas whiteboard (mind maps, quizzes, document summaries, countdown timers, an "interactive app generator"); students watch live in any browser via a room code.

**Model and agent design.** Speech (Bahasa Indonesia or English) → Gemma 4 → **structured function calls** on the canvas, e.g. `add_mindmap_node("Pujangga Lama","center","primary")`, `connect_nodes(...)`. The system prompt is English, input Indonesian, output English function calls: no translation layer, no fine-tuning. Each request carries a **base64 PNG screenshot of the canvas plus a JSON dump of all canvas objects**, so Gemma makes spatially aware placements (vision + text). Routing: **gemma-4-31b-it in the cloud** and **`gemma4:e2b` via Ollama** offline, switched automatically on connectivity (`AI_MODE=ollama`); E2B "fits in 4GB RAM"; offline mode is "how Trido gets used 40% of the time" (writeup). An animated agent cursor moves along Bezier curves to each target before executing, which students started following with their eyes.

**Key negative finding.** Smaller models gave silent failures: wrong types, missing parameters, free text instead of a call. Gemma 4's instruction following made function calling reliable enough for live class.

**Voice.** Dual path: Web Speech API for an instant preview and a MediaRecorder capture sent to **Gemini** transcription when browser confidence is low; the more confident wins (so ASR is partly cloud, not Gemma). The video uses Google AI Studio App Builder for cloud prototyping; the repo and live demo show local Ollama.

**Systems.** Socket.IO broadcasting canvas *deltas* to 30+ student devices, < 500 ms on 3G (writeup); IndexedDB autosave every 3 s; Express + Socket.IO backend on Railway/Render, static frontend on Vercel.

**Evaluation.** Usage observation from six weeks of classroom use: mind maps in 100% of sessions, quizzes several times per week; app generator takes 1 to 2 minutes so it became a prepared-lesson feature. "95% reduction in required physical interaction" is a team claim without a protocol. No model-level eval.

**What judges said (host):** "hybrid architecture between cloud-hosted and on-device Gemma models to translate Bahasa Indonesia speech into structured English canvas function calls" (https://www.kaggle.com/competitions/gemma-4-good-hackathon/discussion/736681). The writeup lists its own submission track as Digital Equity & Inclusivity + Ollama; it was awarded Main 2nd instead.

### Main 3rd: PenguinAgent (And0Sha)
**Problem and user.** Small polar research teams (e.g. Antarctic expeditions) with no internet and confidential field footage, who cannot afford to watch thousands of hours of video to track penguin behaviour, demographics and climate effects. The writeup self-labels its track as Health & Sciences / Global Resilience; it was awarded Main 3rd.

**Pipeline (local Streamlit app).**
1. *Tracking:* **SAM 3** masks and trajectories per penguin, giving bbox area, position and velocity (Vx, Vy) every second. Memory engineering: downscaled 1 fps proxy video, 10 s chunks each in a disposable subprocess with PyTorch cache clearing; trajectories re-stitched across chunk boundaries with a spatial cost matrix and the **Hungarian algorithm**.
2. *Species ID:* **SigLIP 2 + a linear probe** over 18 penguin species. Negative result: SigLIP 2 zero-shot separates penguins from non-penguins but not the 18 species, so the author built a per-species image dataset (in the repo under `dataset/<species>/`) and trained the probe. Probe accuracy is not reported.
3. *Reasoning:* **Gemma 4 26B via Ollama** (`gemma4:26b` default per README; the writeup itself does not name the size) receives sampled frames plus the JSON telemetry, with native function calling over two tools: `search_scientific_literature` (offline RAG: LangChain + `BAAI/bge-m3` embeddings + FAISS over 24 listed ornithology books/papers) and `generate_custom_chart` (writes and executes matplotlib code). Tool loops capped at **max 3 turns** after it got stuck recursing.
4. *Reports:* markdown scientific reports with charts and clickable citations; an "Anomaly Index" per penguin from Uniqueness, Anormality and Rarity, computed after the agent answers 100 general + 20 species-specific questions; a thermodynamic huddling analysis.

**Hardware.** Ubuntu 26.04, RTX 5080, **512 GB system RAM** (the author leans on it for long multimodal contexts), 720p at 1 fps. "Edge" here means a field workstation, not a phone.

**Fine-tuning:** none for Gemma (only the SigLIP probe). **Evaluation:** none quantitative (no probe accuracy, no report-quality check, no expert comparison). Modalities: video frames + text. **What judges said (host):** "combining computer vision with agentic reasoning ... extracts kinematics and identifies species ... locally deployed Gemma 4 26B model to analyze behaviors, detect anomalies, and contextualize findings against scientific literature" (736681). Video https://www.youtube.com/watch?v=2qPwO_nelEY.

### Main 4th: DEMENTOR, Edge AI Triage for Dementia Care (Inchara)
The Kaggle writeup is THIN (~600 words; ends at the JSON schema), so this section adds the repo README (github.com/hash066/dementia) and the LoRA's `adapter_config.json` on Hugging Face (`Inchara20/gemma4-dementia-lora`; the model card itself is the empty template).

**Problem and user.** A named story: Savitha, a retired teacher with dementia who walked out and was lost for two hours. Problem: untrained family caregivers can't tell "a bad day" from "needs the ER"; signals (speech, falls, panic button) live on separate devices; generic chatbots diagnose or downplay confidently.

**Architecture (four layers).** (1) ESP32 wearable: mic stream, IMU, camera, help button. (2) Raspberry Pi edge hub: **Vosk** offline STT, fall/button `EventEnvelope` forwarding, camera frame capture on FALL. (3) "Phone core" FastAPI hub: encrypted event store, SQLite + FTS5 memory index, Gemma 4 native function-calling router, vision on fall frames. (4) Android caregiver app: timeline, memory-assistant chat with full-day context, SSE-streamed triage. Canonical event types AUDIO / SPEECH / FALL / EMERGENCY / IMAGE / OBJECT / REMINDER / VITALS / SYSTEM. "Safety logic must stay outside the model."

**Model and fine-tune.** `google/gemma-4-E2B-it`, fine-tuned with **Unsloth LoRA** from `unsloth/gemma-4-e2b-it-unsloth-bnb-4bit` (QLoRA base), **r = 16, alpha = 16, dropout 0**, targets q/k/v/o + gate/up/down (adapter config). Exported to **GGUF q8_0**, served with **llama-cpp-python**. When speech suggests symptoms or medications, function calling routes to this specialist head, which must emit strict JSON only: `urgency` (none/low/medium/high/critical), `follow_up_questions`, `caregiver_summary`, `safety_note`, and `posture_assessment` (only on FALL, from the fall-camera frame). Training data size and source, lr and epochs are not given anywhere read. Modalities: text (Vosk transcripts) + image (fall frames). Gemma's own audio input is not used for STT.

**Evaluation:** none reported (no JSON-validity rate, no triage accuracy). Demo https://dementor-ten.vercel.app/, video https://youtu.be/ajElYdGzkZ0, mock-pipeline scripts to run without hardware. Positioned as caregiver support, not a diagnostic device. Host: "edge orchestration pipeline that streams real-time triage updates ... voice transcripts and fall camera frames from wearable sensors and hubs into a local Gemma 4 E2B model" (736681).

### Impact: Health & Sciences: Project Rosie (shashank padala)
**Problem and user.** Veterinary oncologists with no ML training who want personalised neoantigen mRNA cancer vaccines for dogs. Motivated by Paul Coningham, an Australian ML veteran who spent three months with a university lab designing such a vaccine for his dog Rosie. The design pipeline needs pVACtools, NetMHCpan, codon optimisation and IVT chemistry expertise vet clinics lack.

**System (cloud, not on-device).** A vet uploads a tumour VCF; a deterministic Python pipeline on **Cloud Run Jobs** (8 GiB, 4 CPU, 3 h timeout) runs in under an hour at ~$15 per case (writeup): Ensembl VEP with the canine ROS_Cfam_1.0 cache → pVACtools + NetMHCpan via IEDB → a transparent ~50-line composite scorer → Biopython mRNA design with a canine codon table → a Jinja synthesis spec. Output: ranked neoantigens, synthesis-ready multi-epitope FASTA, a plain-language clinical report and an mRNA synthesis specification for a contract manufacturer. Next.js 16 on Vercel, Supabase (Postgres, RLS, Realtime stage callbacks, no polling), GCS.

**Model.** **Gemma 4 26B-A4B (MoE), `gemma-4-26b-a4b-it-maas` via Vertex AI**. No fine-tuning. Four roles:
1. *Pre-flight VCF advisor:* browser parses structural facts (variant count, INFO keys, sample columns, SOMATIC flag, chromosomes, FILTER) and Gemma flags issues before an hour of compute is spent (e.g. no SOMATIC flag and no NORMAL column → germline contamination). Strict JSON with safe-parse fallback; never blocks submission.
2. *Multimodal report writer:* reads the candidate JSON plus two PNG charts (binding-affinity bars, mutation-landscape pie) and writes a 400 to 600 word clinical report; a species switch in the system prompt swaps DLA/HLA/FLA terms and IC50 interpretation (off-the-shelf Gemma defaulted to human oncology framing).
3. *Sensitivity narrator:* IC50 and VAF sliders re-rank client-side with zero LLM cost; Gemma only narrates the trade-off on request.
4. *Case chat* with full case context in the system prompt.

**The one transferable idea.** "AI for interpretation, deterministic code for compliance": they first let Gemma write the CMO synthesis spec, then replaced it with a template because one hallucinated catalog number or drifted QC threshold would discredit the tool (fixed science: CleanCap AG, 100% m1Ψ, SM-102 LNP at 50:10:38.5:1.5, RIN ≥ 8.0). Other explicit trade-offs: VCF not FASTQ (Phase 2), VAF as a clonality proxy instead of PyClone-VI, AlphaFold excluded on ROI.

**Evaluation.** No quantitative eval. One expert review (a Senior Research Associate at Case Comprehensive Cancer Center: "credible MVP"). An honest-limitations section; the demo dataset was synthetically enriched across PIK3CA, TP53, BRCA2, KIT, PTEN because real canine runs gave one candidate and trivial charts. Live app https://rosie.kiraklabs.com, demo /demo, docs on key decisions and pipeline architecture in the repo, video youtu.be/HRn4zM7KbEQ.

### Impact: Global Resilience: Acuífero·Vigía (5-person team)
**Problem and user.** Flash floods in Argentina's Litoral region (Bahía Blanca, 7 Mar 2025: 290 to 400 mm in a morning, 17 dead; Santa Fe 2003). National alerts (SINAGIR/SINAME) work at provincial scale, assume the network is up, and don't understand Rioplatense Spanish. Users: municipal civil defence offices and neighbours.

**Four pillars, one model family.**
1. *Acuífero nodes:* Raspberry Pi 5 (8 GB) + fixed camera. An **OpenCV "deterministic firewall"** checks water level against a reference marker every frame; only on a meaningful change is **Gemma 4 E2B on LiteRT-LM** invoked for temporal visual reasoning and a structured observation.
2. *Vigía app* (Android/PWA): citizens report by voice or text; **Gemma via MediaPipe on the phone** structures each report into {location, phenomenon, severity, time}; reports queue offline and send when connectivity returns. Dialect handling is by **prompting with Rioplatense exemplars and a typed schema** (urgency particles like "dale, che, mirá" encoded as a severity signal), not fine-tuning.
3. *Decision Engine:* FastAPI on a laptop, **Gemma 4 E2B via Ollama** (OpenAI-compatible endpoint) fusing node observations, citizen reports and meteorological data into Spanish alerts that carry their reasoning chain (inputs, weights, thresholds crossed). **The LLM is never on the critical path:** a rule-based fallback emits the alert if Gemma is slow, absent or malformed. Optional E4B "Thinking Mode" via an env var where VRAM allows.
4. *SINAGIR-ready:* native function calling maps each alert to the national schema (event type, severity, geographic IDs, evidence).

**Model ablation.** E2B vs E4B on the same Pi 5: E4B's multimodal pipeline hit **WebGPU buffer overflows** and CPU fallback blew the latency budget; E2B passed (ablation documented in the repo).

**Measured results (writeup; the most complete on-device numbers among the winners).**
- Pi 5 + LiteRT-LM, held-out water-level frames from one reference site: engine creation 1.189 s; cold first image inference 23.944 s; **warm median 22.86 s per frame** (range 22.758 to 23.211 s); peak RSS 2,941.5 MB (node) / 2,592.7 MB (benchmark); analysis cadence 53 to 54 s against a 300 s budget; PMIC power idle 1.73 W, warm 4.29 to 4.58 W, peak 8.43 W.
- Vigía structuring on mid-range Android, held-out hand-annotated Rioplatense transcripts (set size not stated, internal): **exact-schema match 82%; field F1 location 0.88, phenomenon 0.93, severity 0.85; median 900 ms**.
- End-to-end alert latency median 0.9 min, p95 2.2 min; fallback-only 0.3 s.
- "What we have not yet measured": no field durability, no back-test against historical SMN alerts (planned months 3 to 6), visual accuracy from a single site.

**Fine-tuning:** none. **Modalities:** image (nodes), audio/text (citizen reports via MediaPipe), text (fusion). Apache 2.0; code github.com/LucasErcolano/AcuIfero4Vigia, a Kaggle replay notebook of live hardware runs and a Kaggle dataset of demo artifacts, video youtu.be/NjHCn_lJJ2k. Three runtimes (LiteRT-LM, MediaPipe, Ollama) for one model.

### Impact: Digital Equity & Inclusivity: Gem-Care (Bilal Bounajma)
Bank covers the headline (context prompting hurts; fine-tune gives WER 19.0% vs 32.7% audio-only base vs 39.5% base + context). New facts from the writeup and repo README (github.com/BBounajma/Gemma4-hackathon):

**Problem.** ASR collapses on dysarthric speech (Parkinson's, ALS, cerebral palsy, Down syndrome, stroke). Human listeners use clinical context; the hypothesis is that an audio-language model could too.

**Data.** **Speech Accessibility Project** (UIUC Beckman Institute; used with official approval, not redistributed), each sample annotated with diagnosis, transcript and per-dimension severity ratings; plus the team's own **BF-SPRACHE**, claimed as the first annotated impaired-German test set (size not stated). Speakers shuffled each epoch.

**Prompt design.** A structured clinical-context template: diagnosis, a plain-language description of how it sounds acoustically, and an eight-dimension speech profile (naturalness, consonant precision, pitch variability, vowel quality, voice quality, speech rate, intelligibility, pitch level) each rated 1 to 7, ending with "Output ONLY the transcription, no explanations". Ablation conditions in the repo: A0 audio only; P1 diagnosis; P2 diagnosis + all severity tiers; P2a/P2b/P2c tier subsets; P3 P2 + a follow-up correction loop. Diagnosis of the failure: narrative, non-instructional context makes vanilla Gemma emit clinical-flavoured text instead of a transcript, worse with longer context.

**Fine-tune recipe (README).** Gemma 4 E2B, PEFT LoRA with **audio_tower and vision_tower excluded** (so it adapts the language model's use of audio embeddings, not the encoder), rank 16 on Q/K/V (3.1 M trainable of 5.1 B, 0.06%), alpha 32, dropout 0.05 (per `lora.py` notes), **bf16, lr 1e-4, grad-accum 32, ~8.5 h**, best checkpoint by dev WER each epoch. Framework is plain PEFT/transformers (not Unsloth). Per-epoch test WER (normalised): 28.4, 27.0, 22.9, 21.7, 20.9, **19.6%** at epoch 6 (headline 19.0% presumably a different split or normalisation; UNVERIFIED). Eval: greedy decoding, regex-strip preambles ("The transcription is:"), WER vs both original and disfluency-cleaned transcripts taking the minimum (a lenient choice worth noting).

**Missing control.** The repo has an audio-only LoRA config (`gemma4_e2b_a0_lora.yaml`) but the README table does not report it, so how much of the 32.7 → 19.0 drop comes from the clinical context vs from fine-tuning on dysarthric audio at all is not shown.

**Product features.** Language pick or auto-detect, an optional multi-pass "smarter suggestions" mode, a per-word confidence score for downstream risk mitigation, and a review loop where users correct and store transcripts to build a personal fine-tuning set. Runs on consumer devices (no runtime/quantisation named). Model on Kaggle Models (`bilalbounajma/gem-care-demo`), video youtu.be/k0l-NgnjGZE (contains a minor; team asks not to share publicly without guardian approval).

### Impact: Safety & Trust: TrueVoice (Shiwon Oh: shiwoni, hyeminss11)
**Problem and user.** Voice-clone phone scams aimed disproportionately at the elderly (writeup cites Trend Micro 2026, FBI IC3 2025 $893 M AI-related losses, Deloitte's $40 B by 2027 projection). Enterprise anti-spoofing is API-bound and expensive; research systems aren't deployable. Goal: a no-install browser tool that gives a verdict in seconds.

**Model.** **Gemma 4 E4B (`google/gemma-4-e4b-it`) used only for its `audio_tower`.** Raw audio → Gemma 4 processor mel spectrogram → **frozen** audio tower → 1,536-d hidden states → mean-pool over time → head Linear(1536→256) → GELU → Dropout 0.3 → Linear(256→2). Only the **1.5 MB head** is trained. The language model is never used for generation: this is representation reuse, not an LLM application.

**Data and training.** **ASVspoof 2019 LA** train/dev (train 25,380 = 2,580 real + 22,800 fake; val 24,844), tested on **ASVspoof 2021 LA eval (148,176 clips)**. Key preprocessing: **codec simulation** on all training audio (downsample to 8 kHz, back up to 16 kHz) so the model can't separate real from fake by studio quality, which would fail on phone audio; the 2021 eval has real codec effects natively. On-the-fly collator loads audio per batch (Colab A100). HF Transformers; epochs/lr not stated in the writeup.

**Bug worth recording.** float32 features from the collator hitting the bf16 audio tower produced **NaNs** that propagated through the forward pass; fixed by casting to bfloat16 inside the collator.

**Evaluation (benchmark-grade, with a public standard test set).** **EER 5.20%**, accuracy 96%, fake recall 96%, real recall 93%, fake precision 0.99 on the full 2021 LA eval. Not compared against published ASVspoof baselines in the writeup, and the class imbalance (≈ 9:1 fake in training) is not discussed. ~2 s per clip on an A100.

**Deployment.** A **Gradio web app** (mic recording or upload; "Phone Call Simulation Mode" applies 8 kHz codec). Despite the host's "on-device deepfake detector" wording, the writeup lists moving to E2B for fully on-device offline detection as *future work*; the measured system runs on an A100. English-only training data. Code and weights open: github.com/hyeminss11/true-voice-gemma4; video youtu.be/93UHGvDQdx8. Host: "proving a simple classification head can expose synthetic voice clones in real-time" (736681).

### Special: Cactus: KawanIsyarat (Pradana Yahya)
**Problem and user.** The author's Deaf younger brother, who uses BISINDO (Indonesian Sign Language) and needs a family interpreter at hospitals, schools and offices. Existing tools are ASL-centric or vocabulary libraries, not live two-way communication. Target: a mid-range Android phone, weak or no internet, private conversations.

**Pipelines.**
- *Deaf → hearing:* camera → MediaPipe pose + hand landmarks → a **1D causal depthwise CNN** (inspired by the 1st-place Kaggle ASL Signs solution) over 30-frame windows → BISINDO gloss → Gemma 4 turns gloss into a natural Indonesian sentence plus empathy tips → TTS. **16 BISINDO word classes, 86.2% leave-one-signer-out test accuracy** (writeup). Own datasets published on Kaggle (BISINDO alphabet, BISINDO signs, SIBI training).
- *Hearing → Deaf:* mic → 16 kHz PCM → **Gemma 4 native audio** (`<|audio|>`) transcript → Gemma simplification into short clear Indonesian.
- *Learning:* local Dense classifiers validate SIBI/BISINDO letters first; Gemma 4 vision acts as a *coach*, with a reference library injected into every prompt (26 BISINDO letters, 24 SIBI letters, common word signs) because Gemma doesn't know the hand shapes. Vocabulary/idiom helper, articulation feedback, one-tap SOS phrases.

**Runtime and memory-aware routing (why it won Cactus).** **Gemma 4 E2B INT4 via the Cactus SDK**, fully offline after one download. Fallback: **Whisper Base INT8 via Cactus**, loaded on demand only when Gemma's audio transcript is empty, fails or is too slow, then unloaded so Gemma can reclaim memory. On a **Pixel 6a: ~1.7 to 1.9 GB RAM, ~3.5 to 4.5 tok/s**, Cactus settings `n_ctx: 512`, `memory_f32: false`, `batch_size: 1`, `n_threads: 4`.

**Engineering lessons (each a reusable gotcha).**
- Cactus enabled **thinking mode by default** (`enable_thinking_if_supported`): simple replies took **60 to 153 s**; disabling it brought them to **~4 to 9 s**.
- Raw PCM above ~256 KB caused OOM on the Pixel 6a; long buffers are decimated before Gemma.
- Whisper prompt must end with `<|notimestamps|>` (else timestamp tokens get filtered to an empty transcript): `<|startoftranscript|><|id|><|transcribe|><|notimestamps|>`.
- Disposing the camera on `AppLifecycleState.inactive` froze it when the notification shade opened; dispose on `paused`.

**Fine-tuning:** none of Gemma (only the sign CNN and letter classifiers). Modalities: all three (audio, image, text) through one local model, the only winner with that coverage on a phone. Stack: Flutter, Riverpod, MediaPipe, TFLite, Hive. Code github.com/haipradana/KawanIsyarat, site kawanisyarat.pradanayahya.com, video youtu.be/eiXdkpwouBY.

### Special: LiteRT: Gilbeot (길벗, psymon)
**Problem and user.** Elderly Korean pedestrians who get lost because "turn right in 250 m" doesn't match what they see; they navigate by visible objects ("under the yellow sign"). Thesis: "translate machine coordinates into human coordinates". On-device because subway stations and underground malls have bad networks and voice/photos reveal location. Target Galaxy phones (Korea Gallup 2025: 92% of people in their 60s, 82% of 70+). Tested with the author's father-in-law.

**Flow.** Spoken destination → **Gemma 4 audio** Korean transcript → T-Map/ODsay route + Naver Map → user photographs a confusing spot → **Gemma 4 vision** reads signs, exits, arrows, entrances → simple Korean instruction ("walk left below the yellow Exit 10 sign") → GPS-polyline Haversine off-route check (**if off-route, guidance is suppressed** so the VLM can't hallucinate from an unrelated scene) → TTS. Two APKs: a judge demo with fixed WAV/route/photos that still runs real inference every time, and a Korea production build.

**Fine-tune (audio, Unsloth).** Base `gemma-4-E2B-it-litert-lm` scored **13.14% CER** on a 134-utterance Korean held-out set. Trained on AI Hub *Command Speech (Elderly Male/Female)*: **45,823 utterances, ~50 h**, with **Unsloth FastModel + PEFT, 4-bit**, **rank-8 LoRA on the audio encoder + LM attention/MLP**, which required training Gemma 4's custom `Gemma4ClippableLinear` layers. Deployed CER **5.00%** (~62% relative reduction).

**Deployment engineering (the reason it won LiteRT).** No official way existed to put a Gemma 4 audio LoRA into an Android `.litertlm` bundle: the LiteRT-LM converter didn't support the audio path shape, `litert-torch-nightly` exported LM only, MediaPipe LLM was attention-only/GPU-centred. They wrote a patcher using **same-grid requantisation**: `patched_int4 = clip(round((base_fp32 + LoRA_delta) / scale), -8, 7)`, keeping the original quant scale; LM LoRA is grafted into the bundle, the riskier audio adapter is attached as a runtime sidecar (`loraPath`, alpha 8). Bundle ~2.4 GB: vision encoder ~208 MB, audio encoder ~102 MB, LM prefill/decode ~781 MB, per-layer embedder ~1.2 GB, **MTP drafter ~42 MB**.

**Runtime comparison (same harness, relative seconds).** LiteRT graft+sidecar CER 5.003%, 12.48 s/sample; Cactus INT8 3.949%, 41.94 s; Cactus INT4 4.856%, 45.32 s. Cactus was more accurate but ~3.4× slower, past the S10e budget; they upstreamed a byte-fallback detokenisation fix (cactus-compute/cactus#635).

**Vision safety.** VLMs flip left/right; Gemma read signs and exit numbers well but sometimes flipped arrow words. Fix: the model emits **arrow tip/tail x-coordinates (bbox-style)** and deterministic code decides direction, overriding the sentence if it conflicts with the pixels.

**Latency policy per device.** Galaxy S23 (Snapdragon 8 Gen 2, Adreno 740) GPU + **MTP speculative decoding: decode 17.8 s → 11.5 s, ~12 s per photo**; Galaxy S10e (Exynos 9820) CPU/XNNPACK with MTP **off** (~50 s per photo), because on CPU the drafter and main model share compute and the LoRA path lowers acceptance below breakeven.

**Eval:** CER on a 134-utterance held-out set with base vs fine-tuned vs Cactus; device latency table. No vision accuracy number. Technical report, architecture doc and patcher in github.com/psymon-ai/gilbeot-public; model huggingface.co/psymon/gilbeot-korean-audio-litertlm; video youtube.com/watch?v=jg-FSf5QdNI. CC BY 4.0.

### Special: Ollama: PathOS (getalife(); Dhairya Pandya, Shantanu Kharwar, Rounak-agrwl)
**Problem and user.** The first-pass H&E histopathology screen in under-served labs (rural Gujarat: one pathologist per ~half a million people, 80 to 100 slides/day reviewed vs 200 to 400 arriving; pathologists per 100k: Sub-Saharan Africa 0.3, India 1.2, US 5.7). Goal: an "AI resident" producing a draft report for same-day pathologist sign-off, on a CPU laptop, offline.

**Model and data.** **Gemma 4 E2B**, fine-tuned multimodally with **Unsloth** (4-bit + LoRA with `finetune_vision_layers=True`, which the team stresses most people skip; 8.2 GB allocated on a T4 15.6 GB). Data: **PathVQA ×2 augmented 10,000; QUILT-LLaVA-Instruct-107K subset 4,000; NCT-CRC-HE-100K 2,700 (9 tissue classes)**. Resolution raised **224 → 448 px** after a peritoneum patch was described as "cross-sections of multiple fish". Custom lazy-loading dataset (loading 800 PIL images killed the kernel).

**Three-stage training story.**
1. *SFT v1:* 26% overall; **82% of yes/no errors were refusals/hedges** ("I cannot confirm...") inherited from RLHF; 600 SFT steps couldn't override it.
2. *v2:* `<answer>...</answer>` tags for exact-match eval + **GRPO with four rewards**: `reward_no_hedge` (−1.0 on hedge language), `reward_yn_accuracy` (+1.0 exact, −0.5 opposite), `reward_format` (+0.3 tag present, −0.5 missing), `reward_open_accuracy` (+0.5 if ground-truth words appear). Slogan: "SFT teaches what to say. GRPO teaches what not to say."
3. *v3 distillation:* raw `ollama run` scored ~35% while their Python inference engine scored ~90%+ thanks to self-consistency voting, RAG few-shot injection, CoT routing, constrained decoding and confidence-gated retry. They ran the engine as a teacher on 5,000+ pairs, kept only high-confidence outputs and SFT'd them back into the weights ("compress test-time compute back into the weights").

**Evaluation (writeup).** Base E2B ~50% yes/no, ~0% open, ~25% overall; v1 32 / 20 / 26%; v2 44% yes/no, 35% overall; **v3 88% yes/no on a 100-sample PathVQA validation set**, single forward pass. Caveats: small validation set, PathVQA yes/no only for v3 (open-ended not reported), training data includes PathVQA (augmented ×2) so the val set is in-distribution. Eval notebook kaggle.com/code/dhairyapandya24/pathos-evals-4bit.

**Agentic report.** Native function calling over a five-tool chain `analyze_patch() → flag_malignancy() → suggest_special_stains() → compare_to_atlas() → generate_report()` producing a structured lab report (tissue type, finding, morphology, clinical implication, confidence, pathologist note).

**Deployment.** `ollama pull dhairyapandya/pathos` (no Python); raw **GGUF Q4_K_M ~2.5 GB** via llama.cpp for air-gapped use, "runs on a Raspberry Pi 5" (no speed given); LoRA adapter ~150 MB; HF repos for distilled, distilled-RL and GGUF weights; training code, reward functions and distillation pipeline public. Compute: ~100 h of Kaggle GPU quota (P100 incompatible with the PyTorch CUDA build, sm 6.0 < 7.0; 19.5 GB working dir filled, fixed by writing to `/tmp`). Videos youtu.be/bIeqx_HEBRs, youtu.be/aIpTKX7F4eU.

### Special: Unsloth: MindBridge (Huzayfah Patel)
**Problem and user.** ASHA community health workers in rural India (example: Barabanki, Uttar Pradesh) who know the PHQ-9 exists but have no Hindi form or workflow for a 20-minute home visit; the motivating patient is a postpartum mother. Context cited: 84.5% treatment gap (NMHS 2015-16), ~19% pooled postnatal depression prevalence in India. Author is a UK psychiatrist.

**Product.** Hindi-first iOS app: per PHQ-9 (9 items) and GAD-7 (7 items) question, the ASHA reads the item, the patient answers in her own words, one tap records it, and **Gemma 4 E2B's USM conformer audio encoder** maps the WAV to `{score 0-3, rationale, confidence}` in one multimodal forward pass ("No separate ASR"); Likert buttons as fallback; a "why" drawer shows the reasoning chain. **Data (3 phases).** (A) **144 hand-authored seeds** (120 routine PHQ-9/GAD-7 across 3 personas + 24 Item-9 adversarials held out), co-written with the author's father, a native Hindi speaker; (B) expansion with **Gemma 4 26B-A4B on Vertex AI** using MMR-diversified in-context seed selection (λ = 0.65, k = 7) to ~3,000 candidates; (C) sampled review gate. A phone-dictation error turned a self-harm euphemism into "make yourself happy"; bilingual two-rater review caught it.

**Fine-tune recipe (Unsloth).** `FastModel` QLoRA, **r = 16, alpha = 32, 2 epochs, lr 2e-4 constant**, targets q/k/v/o/gate/up/down, **audio modules excluded by construction** (explicit `requires_grad_(False)` on `audio_tower` as a contingency), `adamw_8bit`, bf16, seed 3407, Colab Pro+ A100, ~30 min.

**Evaluation (the only winner with a pre-registered gate).** A hierarchical **kill gate fixed before training**: Format (JSON validity ≥ 95%) → Safety (Item-9 sensitivity ≥ 90%) → Utility (Likert accuracy delta ≥ 10 pp). Caveats disclosed: the 200-row main set is in-distribution, single clinician annotator, no inter-rater study.

**Deployment numbers.** **Cactus React Native**, INT8-apple quantisation preserving the USM audio encoder, encoder on Apple Neural Engine where available, decode on CPU SIMD, memory-mapped per-layer embeddings. E4B INT4 decoded at **0.1 tok/s** on device (60× under their 6 tok/s gate) → switched to **E2B INT8-apple at 9.35 tok/s** within 24 h. **Discrepancy.** The host says MindBridge used "Unsloth to fine-tune Gemma 4 E2B's native audio layers"; the writeup says audio modules were excluded and only language-model projections were tuned (the model still consumes audio through the frozen encoder). ## Consensus vs divergence

- **Table stakes:** E2B-class model, offline or on-device story, a specific underserved user (often a named family member: brother, father, father-in-law, sister), a video, open code, and (8/14) structured JSON or function-call output rather than free chat.
- **What the Main podium had that the track prizes didn't:** scale of the *system* rather than of the model work. GEM-4 is a full research stack (VLA + data tooling + benchmark); Trido is a product used for six weeks in a real classroom; PenguinAgent is a multi-model CV + agent pipeline; DEMENTOR is a four-layer hardware/software stack. Interestingly, the podium is *weaker* on measured evaluation than several track winners: 2 of the 4 podium writeups report no quantitative eval, while Gilbeot, Acuífero·Vigía, MindBridge, PathOS and PreVillage each report baselines. As in Gemma 3n, the 70% non-technical rubric (impact + video) decides places.
