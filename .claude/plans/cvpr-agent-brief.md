# Drafting-agent brief: CVPR 2025 + 2026 paper series

You write ONE paper-analysis post. Follow the paper-writer skill (`.claude/skills/paper-writer/SKILL.md` and the references it tells you to read at each phase), with these overrides from the user:

1. **Length 3,000–4,000 words** (body). This series overrides the skill's default 2,000–3,000 window: run the paper-writer gate as `WORD_MIN=3000 WORD_MAX=4000 bash .claude/skills/paper-writer/scripts/verify-paper-post.sh <post.md> <slug>` (tell `post-verifier` to prefix those two variables). Every gate, including word-count, must pass. Set `readTime` = (words+110)/220, using integer division.
2. **Easy to read, no wall of text.** Paragraphs ≤ 4 sentences. Explain each technique with the ladder (problem → analogy → mechanism → math with every symbol defined → tiny worked example → when it fails). Use tables and short bullet lists. Put a figure about every 400–500 words.
3. **Many figures, 7–9 total, and they must SHOW, not list.** ≥3 cropped from the PDF as `<slug>-fig<n>.webp` (teaser/qualitative results, architecture, key plots, a results table). ≥3 redrawn Excalidraw as `<slug>-<n>.webp`. The user explicitly does NOT want redrawn figures that are just text boxes joined by arrows. Each redrawn figure must carry a visual idea: geometry (cameras, rays, frustums, point clouds, a splat's density profile, a pixel grid, token layout, attention pattern), a plotted curve or comparison of shapes, a before/after, or a data-flow with tensors drawn as shaped blocks with their dimensions. At most ONE pure pipeline/flow diagram per post. Delegate all redrawn figures to the `figure-author` subagent in a single dispatch, passing it this requirement verbatim. Tell it to summarise its reviewers' verdicts and return only the manifest. Never open a WebP yourself. Save extracted paper figures as lossy WebP (`cwebp -q 88`, max width 1792 px); keep each under ~500 KB.
4. **Target file:** overwrite the existing stub `content/blog/paper-reading/computer-vision/<slug>.md`. The slug is the filename and must not change. Frontmatter: category "paper-reading", subcategory "Computer Vision", author "Hiep Tran", date/publishDate "2026-10-15", featured true, plus the `paper:` block from the skill. Keep the stub's tags (area, `cvpr-<year>`, `cvpr-<year>-<tier>`). Read the stub first.
5. **"Where this goes next"** section near the end: turn the follow-up note from the orchestrator into 3–5 concrete follow-up research ideas (each: the question, why the paper makes it tractable now, a first experiment). The user picks these papers because they can be extended into new papers, so this section matters.
6. **No em dashes** (and no spaced en dash or ` -- `) anywhere, figure text included. Never write `$` followed by a digit; brace-wrap inline math that starts with a digit (`${2}x$`). Never put a raw `<`+letter inside math (use `\lt `).
7. **Faithful.** Read the actual paper (arXiv version first; `scripts/get-paper.sh`; the CVF openaccess PDF is the fallback). Every number traces to the paper. Flag extrapolation as yours. Include "what would change my mind" and a References section with the paper URL. If it finds ink within 3 px of the edge, the figure is clipped: have it re-rendered.
