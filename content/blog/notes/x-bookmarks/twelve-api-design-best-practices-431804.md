## Summary

The post lists 12 API design best practices for backend developers, often asked in interviews. The visible ones are clear resource names, using nouns such as GET /orders rather than verbs such as GET /get-all-orders, and standard methods such as POST /users to create and GET /users/123 to read. The text is cut off after that.

## Background

REST API design uses URLs to name resources and HTTP methods to describe actions. Consistent naming makes an API predictable for other developers. Interviewers use these basics to check a candidate's habits.

## What I took away

- Name resources with nouns and let HTTP methods carry the action.
- Use standard methods consistently.
- Open the link for the remaining practices.
